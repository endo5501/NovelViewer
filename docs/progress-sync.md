# 読書進捗の同期

Windows・macOS・iPad のあいだで、小説ごとの読書進捗（最後に開いた話と、その話の中の位置）を Google ドライブ経由で共有します。

## 同期するもの・しないもの

| 同期する | 同期しない |
| --- | --- |
| 小説ごとの最後に開いた話と、その話の中の位置 | 小説の本文、ブックマーク、読み上げの音声、LLM 要約の結果 |

汎用 Web から取り込んだコレクション（`web_` で始まるフォルダ）は、端末ごとにフォルダ名が変わることがあり同じ小説だと判定できないため、同期しません。

データは Google ドライブの「アプリ専用の隠しフォルダ（appDataFolder）」に、端末ごとに 1 つの小さな JSON ファイルとして置かれます。ドライブの一覧には表示されず、アプリはドライブの他のファイルを読み書きできません。

## 使い方

1. 設定画面の「同期」タブを開き、「Google でログイン」を押します。
2. ブラウザ（iPad ではログイン画面）が開くので、Google アカウントを選んで許可します。
3. 同じアカウントで、他の端末でもログインします。

以後は次のときに自動で同期します。

| タイミング | 内容 |
| --- | --- |
| 起動時 | この端末の進捗を送信してから、他の端末の進捗を取得 |
| アプリに戻ってきたとき | 他の端末の進捗を取得 |
| 小説を離れたとき、アプリを閉じる・裏に回すとき | この端末の進捗を送信 |
| 設定画面の「今すぐ同期」 | 送信してから取得 |

同期に失敗しても読書は続けられます。最後に同期した日時と失敗の内容は、設定画面の「同期」タブで確認できます。

ログアウトすると同期は止まります。この端末の読書進捗と、ドライブ上の記録は残ります。

## 他の端末の位置を開く規則

- **この端末にまだ進捗が無い小説**: 他の端末で最後に読んだ話と位置で、確認なしに開きます。まだダウンロードしていない小説の進捗も覚えておき、ダウンロードして初めて開いたときに使います。
- **この端末にも進捗がある小説**: この端末の位置で開いたあと、他の端末の方が新しく別の位置を読んでいれば「◯◯ で N 話を読んでいました（日時）。その位置に移動しますか？」と確認します。「このまま」を選ぶと、その記録については二度と聞きません。
- 開いただけで読み進めていない端末の記録は「新しい」とはみなしません。
- 話は「何話目か」で照合するので、端末ごとにファイル名の桁数（`05_` と `005_`）が違っても同じ話を開きます。その話がまだ無い場合（相手の端末の方が多くダウンロードしている場合）は、更新して話が揃ったときに使います。
- 作者が本文を改稿していて内容が一致しない場合は、その話の先頭から開きます。

新しさの判定には各端末の時計を使います。端末の時刻が大きくずれていると、確認が出なかったり、余計に出たりします。

## ビルドの準備（Google Cloud の設定）

同期には Google の OAuth クライアントが必要です。クライアントの値はリポジトリに含めず、ビルド時に渡します。値を渡さずにビルドしたアプリでは「同期」タブ自体が表示されず、それ以外は普段どおり動きます。

> **すべてのビルドで同じ Google Cloud プロジェクトのクライアントを使ってください。** appDataFolder はプロジェクトごとに分かれているため、別のプロジェクトのクライアントでビルドしたアプリは、同じアカウントでログインしても他の端末の記録が見えません（エラーにもなりません）。

### 1. プロジェクトを作る

1. [Google Cloud Console](https://console.cloud.google.com/) で新しいプロジェクトを作ります（例: `NovelViewer`）。
2. 「API とサービス」→「ライブラリ」で **Google Drive API** を有効にします。

### 2. OAuth 同意画面を設定する

左メニューの「Google Auth Platform」で設定します。

1. 「ブランディング」で、アプリ名とユーザーサポートメール、デベロッパーの連絡先を入力します。加えて、本番に公開するには次の 2 つの URL と承認済みドメインが必要です。ロゴは登録しません（登録するとブランドの確認が必要になります）。

   | 項目 | 値 |
   | --- | --- |
   | アプリのホームページ | `https://endo5501.github.io/NovelViewer/` |
   | プライバシーポリシーのリンク | `https://endo5501.github.io/NovelViewer/privacy-policy.html` |
   | 承認済みドメイン | `endo5501.github.io` |

   2 つのページは、このリポジトリの `docs/index.md` と `docs/privacy-policy.md` を GitHub Pages で公開したものです。
2. 「対象」でユーザーの種類を「外部」にし、「アプリを公開」で公開ステータスを **「本番環境」** にします。「テスト」のままだと、ログインが 7 日で失効し、毎週ログインし直すことになります。
3. 「データアクセス」で次のスコープを追加します。これ以外は追加しません。いずれも審査不要のスコープなので、Google の審査を受けずに使えます。
   - `https://www.googleapis.com/auth/drive.appdata`
   - `openid`
   - `.../auth/userinfo.email`（`email`）

審査を受けていないため、ログイン時に「Google はこのアプリを確認していません」と表示されます。「詳細」→「NovelViewer（安全ではないページ）に移動」で進めます。

### 3. クライアント ID を発行する

「Google Auth Platform」の「クライアント」→「クライアントを作成」で、次の 2 つを作ります。

| アプリケーションの種類 | 用途 | 入力するもの |
| --- | --- | --- |
| デスクトップ アプリ | Windows / macOS | 名前のみ |
| iOS | iPad | バンドル ID `com.endo5501.novelViewer`（App Store ID とチーム ID は空欄でよい） |

デスクトップ用はクライアント ID とクライアント シークレット、iOS 用はクライアント ID を控えます。シークレットは作成直後のダイアログでしか全文を確認できないことがあるので、そこで JSON をダウンロードしておきます。デスクトップ用のシークレットはインストール型アプリでは機密情報として扱われませんが、公開リポジトリには置かないでください。

### 4. ローカルのビルドに渡す

`config/google_oauth.example.json` を **`config/google_oauth.json` という名前でコピーし**、コピーした方の値を書き換えます。`config/google_oauth.json` は Git の管理外です。見本の `google_oauth.example.json` は Git で管理されているので、こちらに本物の値を書かないでください。

```json
{
  "GOOGLE_OAUTH_DESKTOP_CLIENT_ID": "（デスクトップ用のクライアント ID）",
  "GOOGLE_OAUTH_DESKTOP_CLIENT_SECRET": "（デスクトップ用のクライアント シークレット）",
  "GOOGLE_OAUTH_IOS_CLIENT_ID": "（iOS 用のクライアント ID）"
}
```

`scripts/build_app.sh`（Windows は `scripts\build_app.bat`）は、このファイルがあれば自動で読み込みます。別の場所のファイルを使う場合は、環境変数 `NOVEL_VIEWER_OAUTH_CONFIG` にパスを指定します。

開発中に `flutter run` する場合は、ファイルを明示します。

```sh
fvm flutter run -d macos --dart-define-from-file=config/google_oauth.json
```

### 5. macOS 版を開発者証明書で署名する

macOS 版はログイン情報をキーチェーンに保存します。キーチェーンを使う権限（`keychain-access-groups`）は開発者証明書で署名したアプリにしか付けられないため、macOS 版のビルドには署名の設定が必要です。設定が無いと「Runner has entitlements that require signing with a development certificate」でビルドが失敗します。

1. `macos/Runner/Configs/Local.xcconfig`（Git の管理外）を作ります。Team ID は iPad 版の `ios/Flutter/Local.xcconfig` と同じものです。

   ```
   DEVELOPMENT_TEAM = XBPBC9HAGA
   CODE_SIGN_IDENTITY = Apple Development
   ```

2. 初回だけ、この Mac を開発者アカウントに登録し、開発用プロファイルを作ります。

   ```sh
   cd macos
   xcodebuild -workspace Runner.xcworkspace -scheme Runner -configuration Debug \
     -allowProvisioningUpdates -allowProvisioningDeviceRegistration build
   ```

   以後は `scripts/build_app.sh macos` や `flutter run -d macos` でそのままビルドできます。開発用の署名なので、登録した Mac でのみ起動します。

### 6. GitHub Actions のリリースビルドに渡す

リポジトリの Settings → Secrets and variables → Actions に、次の 2 つを登録します（リリースビルドは Windows 版のみなので、iOS 用は不要です）。

- `GOOGLE_OAUTH_DESKTOP_CLIENT_ID`
- `GOOGLE_OAUTH_DESKTOP_CLIENT_SECRET`

登録しないままリリースすると、そのビルドは同期なしになります。

## 困ったとき

| 症状 | 対処 |
| --- | --- |
| 「ログインの有効期限が切れました」と表示される | 「もう一度ログイン」を押す。同意画面が「テスト」のままだと 7 日ごとに起きる |
| 他の端末の進捗が届かない | 両方の端末が同じ Google アカウントでログインしているか、同じ Google Cloud プロジェクトのクライアントでビルドしたかを確認する。設定画面の「今すぐ同期」で最新を取得できる |
| ブラウザで許可してもアプリに戻らない（デスクトップ） | 5 分で待ち受けを打ち切るので、もう一度「Google でログイン」を押す |
| ドライブ上の記録を消したい | Google ドライブの「設定」→「アプリを管理」→ NovelViewer の「オプション」→「隠しアプリデータを削除」 |
