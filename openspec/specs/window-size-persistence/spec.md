## Requirements
### Requirement: ウィンドウサイズの永続化
Windows において、システムはメインウィンドウの幅と高さを永続ストレージへ保存し、次回起動時に復元しなければならない（SHALL）。

#### Scenario: 調整したサイズが次回起動時に復元される
- **WHEN** ユーザーがウィンドウを 1600×1000 にリサイズし、アプリケーションを終了して再度起動する
- **THEN** メインウィンドウは 1600×1000 で表示される

#### Scenario: 既定サイズのまま終了しても復元される
- **WHEN** ユーザーがサイズを変更せずに終了し、再度起動する
- **THEN** メインウィンドウは前回と同じサイズで表示される

### Requirement: 最大化状態の永続化
システムは最大化状態を、通常時のウィンドウサイズとは独立した値として保存しなければならない（SHALL）。最大化状態で終了した場合、保存される通常サイズは最大化される前のサイズでなければならない（SHALL）。

#### Scenario: 最大化状態で終了すると最大化状態で復元される
- **WHEN** ユーザーがウィンドウを最大化した状態でアプリケーションを終了し、再度起動する
- **THEN** メインウィンドウは最大化された状態で表示される

#### Scenario: 復元後に最大化を解除すると最大化前のサイズに戻る
- **WHEN** ユーザーが 1400×900 のウィンドウを最大化してから終了し、再度起動して最大化を解除する
- **THEN** メインウィンドウは 1400×900 で表示される

#### Scenario: 最大化を解除して終了すると通常状態で復元される
- **WHEN** ユーザーがウィンドウを最大化した後に最大化を解除し、その状態で終了して再度起動する
- **THEN** メインウィンドウは最大化されていない状態で、解除後のサイズで表示される

### Requirement: 復元サイズの検証
システムは保存されたサイズを復元する前に検証し、起動時のプライマリモニタの作業領域（work area）を超える場合は作業領域に収まるようクランプしなければならない（SHALL）。また、定義された最小サイズ（幅 800、高さ 600）を下回る場合は最小サイズまで引き上げなければならない（SHALL）。

#### Scenario: 作業領域より大きいサイズがクランプされる
- **WHEN** 3400×1900 が保存されており、起動時のプライマリモニタの作業領域が 1920×1040 である
- **THEN** メインウィンドウは作業領域に収まるサイズ（幅 1920 以下、高さ 1040 以下）で表示される

#### Scenario: 最小サイズを下回る値が引き上げられる
- **WHEN** 320×240 が保存されている
- **THEN** メインウィンドウは 800×600 以上のサイズで表示される

#### Scenario: 不正な保存値は既定サイズにフォールバックする
- **WHEN** 保存された値が負数、ゼロ、または数値として解釈できない
- **THEN** システムは保存値を破棄し、既定サイズ 1280×720 でメインウィンドウを表示する

### Requirement: ウィンドウ位置は永続化しない
システムはウィンドウの表示位置を保存してはならない（SHALL NOT）。起動時の原点は常に既定値でなければならない（SHALL）。

#### Scenario: 移動した位置は記憶されない
- **WHEN** ユーザーがウィンドウを画面右下へ移動して終了し、再度起動する
- **THEN** メインウィンドウは既定の原点位置に表示される

#### Scenario: モニタ構成が変わっても操作可能な位置に表示される
- **WHEN** 外部モニタ接続時に使用したサイズが保存された状態で、外部モニタを取り外して起動する
- **THEN** メインウィンドウはプライマリモニタ内の既定原点に表示され、タイトルバーが画面内に収まる

### Requirement: リサイズ完了時の保存
システムはウィンドウのリサイズが停止してから 500 ミリ秒後に状態を保存しなければならない（SHALL）。連続したリサイズイベントに対して保存処理は 1 回に集約されなければならない（SHALL）。

#### Scenario: リサイズ停止後に保存される
- **WHEN** ユーザーがウィンドウのリサイズを終え、500 ミリ秒が経過する
- **THEN** システムは新しいサイズを永続ストレージへ保存する

#### Scenario: リサイズ中の連続イベントが集約される
- **WHEN** ユーザーが 500 ミリ秒未満の間隔でリサイズイベントを連続して発生させる
- **THEN** システムは中間状態を保存せず、リサイズ停止後に最終サイズのみを 1 回保存する

#### Scenario: 強制終了しても直近の状態が残る
- **WHEN** ユーザーがリサイズ後 500 ミリ秒以上経過してからアプリケーションを強制終了し、再度起動する
- **THEN** メインウィンドウは強制終了前のサイズで表示される

### Requirement: 終了時の保存
システムはウィンドウが閉じられる際、デバウンス待ちの有無にかかわらず現在のウィンドウ状態を保存しなければならない（SHALL）。リサイズ完了イベントを伴わないサイズ変更（Aero Snap や他プログラムによる変更など）も、この保存によって記録されなければならない（SHALL）。

#### Scenario: リサイズ直後に終了しても失われない
- **WHEN** ユーザーがウィンドウをリサイズし、500 ミリ秒が経過する前にアプリケーションを終了して再度起動する
- **THEN** メインウィンドウは終了直前のサイズで表示される

#### Scenario: Aero Snap によるサイズ変更が記録される
- **WHEN** ユーザーが Aero Snap でウィンドウサイズを変更し、アプリケーションを終了して再度起動する
- **THEN** メインウィンドウは Snap 後のサイズで表示される

### Requirement: 最小化中は状態を書き換えない
ウィンドウが最小化されている間、システムはウィンドウサイズおよび最大化状態を保存してはならない（SHALL NOT）。最小化されたウィンドウが OS から報告する位置・寸法は実際の表示状態を表さないためである。

#### Scenario: 最小化したまま閉じても保存値が保たれる
- **WHEN** ユーザーがウィンドウを最小化し、その状態のままタスクバーからアプリケーションを終了して再度起動する
- **THEN** メインウィンドウは最小化する前のサイズおよび最大化状態で表示される

#### Scenario: 最大化したまま最小化しても最大化状態が保たれる
- **WHEN** ユーザーがウィンドウを最大化してから最小化し、その状態で終了して再度起動する
- **THEN** メインウィンドウは最大化された状態で表示される

### Requirement: 終了を遅延させない
ウィンドウ状態の保存処理はアプリケーションの終了を体感できるほど遅延させてはならない（SHALL NOT）。終了操作の後、ウィンドウは直ちに画面から消えなければならない（SHALL）。

#### Scenario: 終了操作が即座に反映される
- **WHEN** ユーザーが Alt+F4 または閉じるボタンでアプリケーションを終了する
- **THEN** ウィンドウは直ちに画面から消え、プロセスは本機能の導入前と同程度の時間で終了する

#### Scenario: 保存処理が失敗してもアプリケーションは閉じられる
- **WHEN** ウィンドウ状態の保存または終了処理が失敗する
- **THEN** アプリケーションは閉じられる（保存の失敗によって終了不能な状態にならない）

### Requirement: 復元の失敗が起動を妨げない
ウィンドウ状態の復元に失敗した場合でも、システムはアプリケーションの起動を継続しなければならない（SHALL）。

#### Scenario: 復元処理の失敗時も起動する
- **WHEN** ウィンドウ状態の復元処理が失敗する
- **THEN** システムは失敗を記録した上で復元をスキップし、アプリケーションは通常どおり起動する

### Requirement: 初回起動時の既定動作
保存された状態が存在しない場合、システムは現行の既定サイズ 1280×720、非最大化状態でメインウィンドウを表示しなければならない（SHALL）。

#### Scenario: 保存値がない初回起動
- **WHEN** 永続ストレージにウィンドウ状態が保存されていない状態でアプリケーションを起動する
- **THEN** メインウィンドウは 1280×720 の非最大化状態で表示される

### Requirement: 対象プラットフォームの限定
ウィンドウサイズの永続化と復元は Windows でのみ有効でなければならない（SHALL）。macOS および Linux における既存のウィンドウ挙動を変更してはならない（SHALL NOT）。

#### Scenario: macOS の起動時最大化が維持される
- **WHEN** macOS でアプリケーションを起動する
- **THEN** 既存仕様どおりメインウィンドウは zoom（最大化）状態で表示され、保存されたサイズによる復元は行われない

#### Scenario: Windows 以外では保存処理が実行されない
- **WHEN** macOS または Linux でユーザーがウィンドウをリサイズする
- **THEN** システムはウィンドウ状態を永続ストレージへ保存しない

### Requirement: 設定 UI を追加しない
本機能は暗黙の挙動として提供され、有効化・無効化のための設定 UI を追加してはならない（SHALL NOT）。

#### Scenario: 設定画面に項目が追加されない
- **WHEN** ユーザーが設定ダイアログを開く
- **THEN** ウィンドウサイズ記憶に関する設定項目は表示されない
