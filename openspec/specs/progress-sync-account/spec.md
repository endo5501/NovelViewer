# progress-sync-account Specification

## Purpose
進捗の同期に使う Google アカウントへのログインと、その状態の管理を扱う。ビルド時に注入する OAuth の設定で機能の有無が決まり、設定画面から利用者がログイン・ログアウトと同期の状態を確認できるようにする。
## Requirements
### Requirement: ビルド時の設定で同期の有無が決まる
同期を使えるかどうかは、実行中のプラットフォームに必要な OAuth クライアントの設定が、ビルド時に注入されているかで決めなければならない（SHALL）。デスクトップ（Windows / macOS）ではクライアント ID とクライアントシークレット、iOS ではクライアント ID が必要である。それ以外のプラットフォームでは使えないものとする。
設定が無いビルドでは、同期に関する画面要素を表示してはならず（SHALL NOT）、それ以外の機能は通常どおり動作しなければならない（SHALL）。
使えるかどうかの判定は、テストで上書きできる形で公開しなければならない（SHALL）。
OAuth クライアントの値は、リポジトリに含めてはならない（SHALL NOT）。

#### Scenario: 設定が無いビルド
- **WHEN** OAuth クライアントの設定を注入せずにビルドしたアプリで設定画面を開く
- **THEN** 同期のセクションは表示されず、他のセクションは通常どおり表示される

#### Scenario: デスクトップでシークレットが欠けている
- **WHEN** デスクトップ向けにクライアント ID だけを注入し、シークレットを注入せずにビルドする
- **THEN** 同期は使えないものとして扱われる

### Requirement: Google アカウントでログインする
システムは、利用者の操作で Google アカウントにログインできなければならない（SHALL）。要求する権限は、Drive のアプリ専用領域（`drive.appdata`）と、アカウントのメールアドレスの取得（`openid email`）だけでなければならない（SHALL）。認可コードの受け渡しには PKCE と `state` の検証を使わなければならない（SHALL）。
デスクトップでは既定のブラウザで認可画面を開き、ループバックアドレス（`127.0.0.1`）だけで結果を受け取らなければならない（SHALL）。iOS では、システムの認証セッションで結果を受け取らなければならない（SHALL）。
利用者がキャンセルした場合、または一定時間内に結果が返らない場合は、ログインしていない状態のままにしなければならない（SHALL）。
長期のトークンは、プラットフォームの安全な保存領域に保存しなければならない（SHALL）。

#### Scenario: ログインに成功する
- **WHEN** 同期のセクションで「Google でログイン」を押し、ブラウザで許可する
- **THEN** 同期のセクションにログイン中のメールアドレスが表示され、続けて同期が実行される

#### Scenario: state が一致しない
- **WHEN** ループバックで受け取ったリダイレクトの `state` が、要求したときの値と一致しない
- **THEN** トークンへの交換は行われず、ログインしていない状態のままになる

#### Scenario: キャンセルする
- **WHEN** 認可画面で許可せずにブラウザを閉じる、または一定時間が過ぎる
- **THEN** ログインしていない状態のままになり、待ち受けは終了する

### Requirement: トークンの更新と失効
システムは、アクセストークンの期限が近づいたとき、または API が認証エラーを返したときに、保存したトークンで自動的に更新しなければならない（SHALL）。更新が拒否された場合（トークンの失効や取り消し）は、「再ログインが必要」の状態にして同期を止め、同期のセクションにそれを表示しなければならない（SHALL）。この状態でも読書は妨げてはならない（SHALL NOT）。

#### Scenario: トークンが取り消された
- **WHEN** Google アカウントの設定でアプリのアクセスを取り消した後に、同期の契機が来る
- **THEN** 同期は行われず、同期のセクションに再ログインが必要と表示される

### Requirement: ログアウト
システムは、利用者の操作でログアウトできなければならない（SHALL）。ログアウトでは、保存したトークンを削除し、取り消しを Google に要求しなければならない（SHALL）。取り消しの失敗は WARNING を記録するだけにしなければならない（SHALL）。また、この端末に保持している他の端末の記録・前回送信した自分の記録・確認済みの記録を消さなければならない（SHALL）。
この端末の読書進捗と、Drive 上の記録ファイルは消してはならない（SHALL NOT）。

#### Scenario: ログアウトしても読書進捗は残る
- **WHEN** ログアウトする
- **THEN** 同期は止まり、この端末で小説を開くと、この端末の読書進捗の位置から開く

#### Scenario: 別のアカウントでログインし直す
- **WHEN** ログアウトし、別の Google アカウントでログインする
- **THEN** 前のアカウントで受け取った他の端末の記録は使われない

### Requirement: 端末の識別
システムは、端末ごとに一意な端末 ID を一度だけ作って保持し、以後はそれを使い続けなければならない（SHALL）。端末名は、プラットフォーム名とホスト名から作らなければならない（SHALL）。端末名は、他の端末で表示する確認の文言に使う。

ホスト名が取得できない場合、またはホスト名が `localhost` の場合は、端末名にホスト名を含めてはならない（SHALL NOT）。端末名はプラットフォーム名だけとする。iOS は利用者が付けた端末名をアプリに渡さず、ホスト名として `localhost` を返すので、それを付けても確認の文言に意味のない文字が増えるだけだからである。

iOS のプラットフォーム名は、OS 名ではなく端末の種別から決めなければならない（SHALL）。iPhone では `iPhone`、iPad では `iPad` とする。iPad と iPhone の両方で同期すると、どちらも iOS なので、OS 名だけでは確認の文言から記録元の端末を区別できないからである。端末の種別を判定できなかった場合は `iOS` としなければならない（SHALL）。iPhone を `iPad` のように、別の種別として名乗ってはならない（SHALL NOT）。

#### Scenario: 再起動しても同じ記録ファイルを使う
- **WHEN** アプリを再起動して送信する
- **THEN** 前回と同じ端末 ID の記録ファイルが更新され、新しい記録ファイルは作られない

#### Scenario: iPhone は iPhone と名乗る
- **WHEN** iPhone で読書進捗を送信し、別の端末がその記録を取得して確認を表示する
- **THEN** 確認の文言の端末名は `iPhone` で始まる

#### Scenario: iPad は iPad と名乗る
- **WHEN** iPad で読書進捗を送信し、別の端末がその記録を取得して確認を表示する
- **THEN** 確認の文言の端末名は `iPad` で始まる

#### Scenario: 意味のないホスト名は付けない
- **WHEN** ホスト名が `localhost` の iPhone で読書進捗を送信し、別の端末がその記録を取得して確認を表示する
- **THEN** 確認の文言の端末名は `iPhone` だけで、`(localhost)` を含まない

#### Scenario: デスクトップはホスト名を付けて名乗る
- **WHEN** ホスト名が `DESKTOP-ABC` の Windows で読書進捗を送信する
- **THEN** 記録の端末名は `Windows (DESKTOP-ABC)` になる

#### Scenario: 種別が分からない iOS 端末は iOS と名乗る
- **WHEN** iOS で端末の種別を判定できなかった状態で読書進捗を送信する
- **THEN** 記録の端末名は `iOS` で始まり、`iPhone` や `iPad` を名乗らない

### Requirement: 設定画面の同期セクション
同期が使えるビルドでは、設定画面に同期のセクションを表示しなければならない（SHALL）。セクションには次を含めなければならない（SHALL）。
- ログインしていないとき: 「Google でログイン」ボタン
- ログインしているとき: メールアドレス、「今すぐ同期」ボタン、最後に同期が成功した日時、最後の失敗の内容（あれば）、「ログアウト」ボタン
- 再ログインが必要なとき: その旨と、ログインし直すボタン

同期の実行中は「今すぐ同期」を重ねて実行できないようにしなければならない（SHALL）。利用者に見えるラベルはすべて `AppLocalizations` から取得し、`app_ja.arb`、`app_en.arb`、`app_zh.arb` のすべてにキーを追加しなければならない（SHALL）。

#### Scenario: ログイン済みの表示
- **WHEN** ログインしている状態で同期のセクションを開く
- **THEN** メールアドレス、「今すぐ同期」、最後に同期した日時、「ログアウト」が表示される

#### Scenario: 今すぐ同期
- **WHEN** 「今すぐ同期」を押す
- **THEN** 送信の後に取得が行われ、終わると最後に同期した日時が更新される
