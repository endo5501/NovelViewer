## Context

LLM要約機能の推論はすべて外部サーバで走る。`LlmClient` の実装は `OllamaClient` と `OpenAiCompatibleClient` の2つで、どちらも `package:http` でHTTPリクエストを送るだけであり、オンデバイス推論のコードは存在しない。したがってiOS対応の本体はモデルの移植ではなく、ネットワーク到達性と操作系の問題である。

現在iOSでこの機能が無効なのは、`PlatformCapabilities.forPlatform` が `llmSummary = !isIOS` としているためで、他に理由はない。その1行の根拠として、コードコメントと `platform-capabilities` および `llm-settings` の仕様書に「iOSのトランスポートポリシーが平文HTTPエンドポイントを塞ぐ」という説明が記録されている。

この根拠は誤りである可能性が高い。iOS上での経路は次のようになっている。

```
package:http
  └─ IOClient
       └─ dart:io HttpClient
            └─ 生ソケット      ← CFNetwork / NSURLSession を通らない
```

App Transport SecurityはNSURLSession/CFNetworkの層で強制される。`dart:io` の `HttpClient` はその外側で動くため、ATSの平文HTTP禁止は適用されない。一方、ローカルネットワークプライバシーはシステムのネットワークスタック側で効くので、使用するAPIに関わらずLAN宛ての接続に適用される。ループバック宛ては対象外である。

つまりiOSにおける実際の制約は次の2点であり、どちらもシミュレータからループバックへ接続する検証には影響しない。

- LAN上のサーバへ接続するには `NSLocalNetworkUsageDescription` と利用者の許可が要る。
- 既定値の `http://localhost:11434` は実機のiPadでは到達先がない。

能力ゲートは4箇所に置かれており、いずれも `llmSummarySupportedProvider` を参照する。設定ダイアログのLLMセクション、テキストビューアの解析開始メニュー項目（横書き・縦書き）、左カラムの解析履歴タブ、ホバーポップアップ内の再解析コントロール。これらはプラットフォームを直接読まずプロバイダ値に依存しているため、能力の導出を変えるだけで振る舞いが追従する。

解析の起動導線はタッチですでに到達可能である。横書きは `contextMenuBuilder` 経由でiOSの選択ツールバーに項目が乗り、縦書きは `touch-context-menu-trigger` が定めた選択範囲内タップで開く。履歴一覧の項目メニューも長押しで開く。

## Goals / Non-Goals

**Goals:**

- iPadシミュレータからMac上のollama / LM Studioのループバックエンドポイントへ接続し、解析の実行から履歴への蓄積までを通しで確認できる状態にする。
- ゲートされていた4つのUI導線をiOSで表示する。
- iOSでLLMを無効にしていた根拠の記述を、仕様書とコードコメントの両方で事実に合わせて訂正する。
- 平文HTTPが実際に通るかどうかを、実装後の手動検証で確定させる。

**Non-Goals:**

- 能力フラグそのものの削除。`llmSummary` は全プラットフォームで真になるが、モデルとゲートは残す。平文HTTPの可否を実機環境で確かめる前に削ると、想定が崩れたときに戻せなくなる。削除は検証が済んだ後の別変更とする。
- マーク語ポップアップのタッチトリガー。
- `ios/` 配下のネイティブ変更。ATSキーもローカルネットワーク権限の記述も今回は追加しない。
- 実機でのLAN接続、接続先IPの入力導線、長時間解析中のサスペンド対策、オンデバイス推論。
- 音声合成とアプリ内アップデートのiOS対応。

## Decisions

### 能力の導出を機能ごとに分ける

`forPlatform` は現在3つの機能をすべて `!isIOS` で導いている。`llmSummary` だけを `true` に切り離す。

```dart
const PlatformCapabilities.forPlatform({required bool isIOS})
  : textToSpeech = !isIOS,
    appUpdate = !isIOS,
    llmSummary = true;
```

代替案として `isIOS` 引数を使わない形へ寄せることも考えられるが、残る2機能が引数を必要とするため署名は変えない。また `llmSummary` が引数を無視することで、この機能がプラットフォームに依存しなくなったことがコード上で読める。

### 能力フラグとゲートを残す

`llmSummary` は全プラットフォームで真になり、常に真の能力という矛盾を抱える。それでも今回は残す。理由は2つある。

平文HTTPが本当に通るかは、この変更を実装してシミュレータで動かすまで確定しない。もし通らなければ1行で元に戻す必要がある。ゲートを削除してしまうと、その復帰が4箇所のUIとテストの再実装になる。

もう1つは、将来のオンデバイス推論の段階で、機種による支援可否という形で能力の区別が復活する可能性があること。Foundation Modelsを使う道はApple Intelligence対応機に限られる。

矛盾の解消は、検証が済んだ後の独立した変更として扱う。

### ゲートを持つウィジェットには手を入れない

4箇所のゲートはいずれも `llmSummarySupportedProvider` の値で分岐しており、プラットフォームを読んでいない。`platform-capabilities` が定めたとおりの構造になっているため、能力の導出を変えるだけで表示が追従する。これらのファイルを触る必要はなく、触るべきでもない。

各ゲートのウィジェットテストはプロバイダをオーバーライドして両方の結果を検証しているので、これらも変更不要である。

### 根拠の訂正をどこに書くか

誤った根拠は4箇所にある。

| 場所 | 内容 |
|---|---|
| `platform_capabilities.dart` のクラスコメント | iOSに欠けているものの列挙に「トランスポートポリシーが平文HTTPを塞ぐ」を含む |
| `llm_summary_providers.dart` の `llmSummarySupportedProvider` コメント | 同様の説明 |
| `platform-capabilities` 仕様 | iOSがどの任意機能も支援しないというシナリオ |
| `llm-settings` 仕様 | セクションを隠す要件に埋め込まれた根拠 |

`llm-settings` の要件そのもの（能力がない場合はセクションを出さない）は維持する。能力モデルに基づく記述であり、プラットフォームに縛られていないため、将来また偽になりうる。訂正するのは末尾の根拠部分だけである。

コードコメント側では、ATSに触れる代わりに、実機でLAN上のサーバへ接続する際にローカルネットワーク権限が要ること、既定のループバックURLは実機では到達先を持たないことを記録する。この情報は後続の実機対応で必要になる。

### 検証はシミュレータのループバックで行う

`flutter run -d <iPad simulator>` でシミュレータに載せ、設定ダイアログでOllamaを選び、既定のURLのまま解析を実行する。シミュレータはmacOSのネットワークスタックを共有するので、Mac上で動くollamaに `http://localhost:11434` でそのまま届く。

この経路にはローカルネットワーク権限のプロンプトが出ない。したがってこの検証で確かめられるのは平文HTTPの可否とUIの挙動であり、LAN接続の可否ではない。両者を混同しないこと。

LM Studioを相手にする場合、`OpenAiCompatibleClient` は `LlmResponseSchema` を無視するため、構造化出力の制約がかからない。応答の形はパイプライン側の後段検証に委ねられる。ollamaを相手にした場合は `format` が送られるので挙動が異なる。UI確認としてはどちらでもよいが、この差は認識しておく。

## 検証結果

iPad mini (A17 Pro) シミュレータ、iOS 26.5 で通しで確認した。

- 設定ダイアログのLLMセクションが表示され、プロバイダにOllamaを選べた。
- 既定のURL `http://localhost:11434` のまま、モデル一覧に Mac 上の `qwen3.6:35b-mlx` が返った。**平文HTTPはiOSで塞がれていない。** ATSはNSURLSessionの層で強制されるという判断が裏付けられ、`llmSummary` を `!isIOS` へ差し戻す必要はない。
- 横書きモードで「アリス」を選択すると、iOSの選択ツールバーに「解析開始(ネタバレなし)」が並んだ。実行すると進捗ダイアログが出て、約2分で完了し、本文中の「アリス」すべてにマークが付いた。
- 縦書きモードで選択範囲内をタップすると、「コピー」「解析開始(ネタバレなし)」「解析開始(ネタバレあり)」のメニューが出た。TTSが非対応のため「読み方辞書に追加」は現れず、能力ゲートが期待どおり働いている。
- 左カラムの解析履歴タブが現れ、「アリス」のスナップショットが1件積まれた。

この検証が答えていないことも明確にしておく。シミュレータはループバック宛てにしか接続しておらず、ループバックはローカルネットワークプライバシーの対象外である。したがってLAN上のサーバへ到達できるかどうかは未確認のまま残る。実機での確認は後続の変更で行う。

## Risks / Trade-offs

平文HTTPが実はiOSで塞がれている → 検証により否定された。上記のとおりシミュレータでモデル一覧の取得に成功している。

常に真の能力フラグが残る → 意図的な一時措置であり、その旨をコードコメントに残す。検証後の削除を別変更として扱うことを提案に明記する。

タッチだけのiPadでマーク語ポップアップに到達できない → この変更の後、iOSでは解析を実行して履歴には残せるが、本文中のマーク語から要約を読む導線が指では開かない。トラックパッドを接続したiPadではホバーが届くため到達できる。機能として片肺になることを認識した上で、タッチトリガーは別変更とする。

実機のiPadで既定URLが無意味 → 設定セクションが表示されるようになるため、実機で既定値のまま試すと必ず失敗する。シミュレータ検証が目的の段階では許容し、実機対応の変更で接続先入力の導線とあわせて解決する。

解析が長時間に及ぶとiPadのサスペンドで中断する → 今回の検証は短いフォルダで行い、サスペンド対策は別途扱う。
