## ADDED Requirements

### Requirement: 発話長に依存しない有界メモリでの codec デコード

Irodori-TTS の codec デコードは、latent 長に比例して増大する単一の計算グラフを構築してはならない (MUST NOT)。latent フレーム数がタイルサイズを超える場合、システムは latent フレーム軸をオーバーラップ付きのタイルに分割して復号し、各タイルのオーバーラップ領域をトリムして連結しなければならない (SHALL)。これにより計算グラフの単一テンソルサイズは発話長ではなくタイルサイズによって決まる。

タイル分割時の出力は、同じ latent をタイル分割せずに復号した出力と一致しなければならない (MUST)。デコーダは Snake1d (要素毎) / Conv1d / ConvTranspose1d / Slice / Add のみで構成され、系列全体に依存する演算を含まないため、オーバーラップが受容野 (片側 8 latent フレーム) 以上であればこの一致は厳密に成立する。したがってオーバーラップは 8 未満であってはならない (MUST NOT)。

latent フレーム数がタイルサイズ以下の場合、システムは分割を行わず単一グラフで復号しなければならない (SHALL)。この経路の挙動は本要求の導入前と変化してはならない (MUST NOT)。

#### Scenario: 長い発話がタイル分割で復号される
- **WHEN** タイルサイズを超える latent (例: タイル 256 に対し 500 フレーム) を復号する
- **THEN** 複数のタイルに分割して復号され、`failed to allocate Irodori-TTS codec graph` を発生させずに 1920 × latent フレーム数のサンプルが得られる

#### Scenario: タイル分割の出力が直接復号と一致する
- **WHEN** 同一の latent を「タイル分割経路」と「単一グラフ経路」の両方で復号する
- **THEN** 両者の出力サンプルが一致する (差分は浮動小数の再結合誤差の範囲に収まる)

#### Scenario: 短い発話は分割されない
- **WHEN** タイルサイズ以下の latent を復号する
- **THEN** 分割は行われず、単一グラフで復号される

#### Scenario: 出力サンプル数が latent 長から一意に決まる
- **WHEN** 任意の長さの latent を復号する
- **THEN** タイル分割の有無に関わらず、出力サンプル数は 1920 × latent フレーム数になる (`target_samples` によるトリム前)

#### Scenario: 不正なオーバーラップが拒否される
- **WHEN** オーバーラップが 8 未満、またはオーバーラップの 2 倍がタイルサイズ以上になる設定で codec を構築する
- **THEN** 構築時に例外が送出される

### Requirement: バックエンド特性に応じた既定タイルサイズ

システムは既定のタイルサイズをバックエンドごとに決定しなければならない (SHALL)。Vulkan バックエンドでは 256 フレーム、それ以外 (Metal / CUDA / CPU) では 512 フレームを既定としなければならない (SHALL)。オーバーラップは全バックエンド共通で 16 フレームを既定としなければならない (SHALL)。

この区別は単一バッファサイズ上限の有無に基づく。Vulkan では一部のドライバ (例: AMD Radeon RX 6800 / Windows) が単一バッファを 2 GiB に制限し、ggml-vulkan は確保前にこの上限で失敗する。CUDA と CPU には上限が無く (`get_max_size` が `SIZE_MAX`)、Metal は上限超過分をビュー分割で吸収するため、より大きなタイルを安全に使用できる。

タイルサイズとオーバーラップはセッションオプション `irodori_tts.codec_decode_tile_frames` および `irodori_tts.codec_decode_overlap_frames` で上書きできなければならない (SHALL)。オプションが指定された場合、バックエンドに関わらずその値を使用しなければならない (MUST)。

#### Scenario: Vulkan で既定タイルが選択される
- **WHEN** Vulkan バックエンドでオプション未指定のまま codec を構築する
- **THEN** タイルサイズ 256 / オーバーラップ 16 が使用される

#### Scenario: Metal で既定タイルが選択される
- **WHEN** Metal バックエンドでオプション未指定のまま codec を構築する
- **THEN** タイルサイズ 512 / オーバーラップ 16 が使用され、20.48 秒以下の発話は分割されない

#### Scenario: オプションがバックエンド既定を上書きする
- **WHEN** `irodori_tts.codec_decode_tile_frames=128` を指定して Metal バックエンドでセッションを構築する
- **THEN** バックエンド既定の 512 ではなく 128 が使用される
