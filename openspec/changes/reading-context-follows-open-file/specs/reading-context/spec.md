## Purpose

読者がいま開いているエピソードから、それが属する小説フォルダとその話一覧を導く規則を定める。ファイルブラウザが `Drawer` に移って以降、ブラウザの現在地は「次に何を読むか探している場所」であって「いま読んでいるもの」ではない。本文まわりの表示と操作が拠り所にするのは後者であり、この capability がそれを名前のあるものにする。

## ADDED Requirements

### Requirement: 読書コンテキストは表示中のファイルから導かれる

システムは、テキストビューアが表示しているファイルから、**読書中の小説フォルダ**を解決しなければならない（SHALL）。ファイルブラウザの現在地を参照してはならない（SHALL NOT）。

解決は次の順に行われなければならない（SHALL）。

1. 表示中のファイルのパス上に登録済み小説フォルダがあれば、その**最も近いもの**。入れ子の深さに依存しない共有ルールに従う。
2. 無ければ、表示中のファイルが直接置かれているフォルダ。メタデータを持たない手動フォルダでも読書は成立するため、そこを小説フォルダとして扱う。

表示中のファイルが無い場合、読書コンテキストは存在しない（SHALL）。

#### Scenario: 登録済み小説のエピソードを開いている

- **WHEN** `<library_root>/narou_n1234ab/0002.txt` を表示している
- **THEN** 読書中の小説フォルダは `<library_root>/narou_n1234ab` である

#### Scenario: 整理用サブフォルダに入れ子の小説

- **WHEN** `<library_root>/完結済み/異世界/narou_n1234ab/0002.txt` を表示している
- **THEN** 読書中の小説フォルダは `<library_root>/完結済み/異世界/narou_n1234ab` である

#### Scenario: 登録されていないフォルダのファイル

- **WHEN** 登録済み小説フォルダを含まないパスの `<library_root>/手動保存/001.txt` を表示している
- **THEN** 読書中の小説フォルダは `<library_root>/手動保存` である

#### Scenario: 何も開いていない

- **WHEN** テキストビューアがファイルを表示していない
- **THEN** 読書コンテキストは存在しない

#### Scenario: ファイルブラウザの現在地は読書コンテキストを変えない

- **WHEN** あるエピソードを表示したまま、ファイルブラウザをライブラリルートや別の小説フォルダへ移動する
- **THEN** 読書中の小説フォルダは変わらない

### Requirement: 読書コンテキストは自身の話一覧を提供する

システムは、**表示中のエピソードが直接置かれているフォルダ**のテキストファイル（`.txt`）を並べた**話一覧**を提供しなければならない（SHALL）。並び順は `file-browser` の数値プレフィックスソートと一致しなければならない（SHALL）。サブディレクトリを含めてはならない（SHALL NOT）。

話一覧のフォルダは、作品名を決める小説フォルダと一致するとは限らない（SHALL NOT be assumed equal）。小説フォルダが自身の中に整理用サブフォルダを持ち、そこにエピソードが置かれている場合、隣り合う話はそのサブフォルダの中の並びである。作品名は最も近い登録済み小説フォルダから、話一覧はエピソードが実際に置かれているフォルダから、それぞれ導かれなければならない（SHALL）。

話一覧は、表示中のエピソードが別のフォルダへ移ったときに取り直されなければならない（SHALL）。読み終えた小説の一覧を保持し続けてはならない（SHALL NOT）。アプリの外で追加されたエピソードが、次にその小説を開いたときに現れないままになるためである。

話一覧は、ファイルブラウザの一覧（`directoryContentsProvider`）とは別に導かれなければならない（SHALL）。ブラウザの一覧はサブディレクトリの列挙・小説タイトルの解決・TTS 状態の読み出しを伴い、そのためにフォルダ別データベースを開く。読書コンテキストに必要なのは並びだけであり、追加のデータベースハンドルを開いてはならない（SHALL NOT）。

読書コンテキストが存在しない場合、話一覧は空でなければならない（SHALL）。

#### Scenario: 話一覧は小説フォルダ自身のものである

- **WHEN** ある小説のエピソードを表示したまま、ファイルブラウザをライブラリルートへ移動する
- **THEN** 話一覧はその小説フォルダのエピソードであり続け、ライブラリルートの内容にはならない

#### Scenario: 並び順はファイルブラウザと一致する

- **WHEN** 数値プレフィックスを持つエピソードが並ぶ小説フォルダの話一覧を取得する
- **THEN** その順序は、同じフォルダをファイルブラウザで開いたときの表示順と一致する

#### Scenario: サブディレクトリは含まれない

- **WHEN** 小説フォルダにサブディレクトリと `.txt` が混在している
- **THEN** 話一覧には `.txt` のみが含まれる

#### Scenario: 小説フォルダのサブフォルダに置かれたエピソード

- **WHEN** 登録済み小説フォルダの中の整理用サブフォルダにあるエピソードを表示している
- **THEN** 話一覧はそのサブフォルダの `.txt` であり、作品名は登録済み小説フォルダのものになる

#### Scenario: 小説を離れて戻ると取り直される

- **WHEN** ある小説を読んだ後、別の小説へ移り、ふたたび最初の小説へ戻る
- **THEN** 話一覧はそのつど取り直され、離れている間に追加されたエピソードが現れる

#### Scenario: 読書コンテキストが無いときは空である

- **WHEN** テキストビューアがファイルを表示していない
- **THEN** 話一覧は空である

### Requirement: 読書コンテキストはフォルダ操作で失われない

フォルダの移動または改名によって、表示中のエピソードのパスが変わる場合、システムはそのパスを新しい位置へ付け替えなければならない（SHALL）。読書コンテキストはパスから解決されるため、付け替えないと存在しない場所を指し続ける。

この付け替えは、ファイルを開く操作として扱われてはならない（SHALL NOT）。何も開いていないためである。開く操作として扱うと、フォルダ名を変えただけでファイルブラウザが閉じる。

フォルダの削除によって表示中のエピソードが失われる場合は、選択を解除しなければならない（SHALL）。読むものが無くなるためであり、移動・改名とは扱いが異なる。

#### Scenario: フォルダの改名は表示中のファイルブラウザを閉じない

- **WHEN** ファイルブラウザで、表示中のエピソードを含むフォルダを改名する
- **THEN** パスは付け替えられるが、ファイルブラウザは開いたままである

#### Scenario: フォルダの改名に追従する

- **WHEN** 表示中のエピソードを含む整理用フォルダを改名する
- **THEN** 表示中のエピソードのパスは改名後の位置へ付け替えられ、話一覧はそこから取り直される

#### Scenario: フォルダの削除では読書コンテキストが消える

- **WHEN** 表示中のエピソードを含むフォルダを削除する
- **THEN** 選択は解除され、読書コンテキストは存在しなくなる

### Requirement: ダウンロードや更新の後、話一覧は取り直される

小説のダウンロードまたは更新によってエピソードが増減しうる操作の後、システムは話一覧を取り直さなければならない（SHALL）。取り直さなければ、更新で増えたエピソードが読書中の話送りに現れない。

ファイルブラウザの一覧を無効化している箇所はいずれも、話一覧も同時に無効化しなければならない（SHALL）。これはフォルダの作成・移動・改名・削除にも等しく適用される（SHALL）。

#### Scenario: 更新で増えたエピソードが話送りに現れる

- **WHEN** ある小説の最終話を読んでいる状態でその小説を更新し、新しいエピソードが保存される
- **THEN** 話一覧に新しいエピソードが現れ、次話への遷移が可能になる

#### Scenario: 中断された更新でも取り直される

- **WHEN** 更新がキャンセルまたは失敗で終わり、そこまでに保存されたエピソードがある
- **THEN** 話一覧は取り直され、保存された分が反映される

#### Scenario: フォルダ操作の後も取り直される

- **WHEN** フォルダの作成・移動・改名・削除のいずれかを行う
- **THEN** ファイルブラウザの一覧と話一覧の双方が取り直される
