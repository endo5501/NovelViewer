# Tasks

各タスクは TDD で進める（テストを先に書き、失敗を確かめてから実装する）。

## 1. 記録への作品URLとタイトルの追加（domain）

- [ ] 1.1 `SyncProgressRecord` に `url` と `title`（どちらも null 可）を加え、`==` と `hashCode` に含める。URLまたはタイトルだけが違う2つの記録が等しくないことを、単体テストで確かめる（design D2）
- [ ] 1.2 `device_progress_codec.dart` の読み書きで `url` と `title` を扱う。次の4点を単体テストで確かめる（design D1）
  - 書き出しに両方の項目が入り、`format` は 1 のままである
  - 項目が無い記録と `null` の記録を読める
  - 項目が文字列でない記録は `FormatException` になる
  - 今の形式（URLが無い）のJSONをそのまま読める
- [ ] 1.3 `buildOwnRecords` / `buildOwnRecord` に、小説ごとのURLとタイトルを渡して記録に付ける。次の2点を単体テストで確かめる（design D2・D3、仕様「更新後の最初の同期で送り直す」「タイトルを変えると送り直す」）
  - 位置が同じなら、URLやタイトルが変わっても `read_at` は前回の値のままである
  - その場合でも、組み立てた記録は前回送った記録と等しくない

## 2. データベース v14 とリポジトリ

- [ ] 2.1 `NovelDatabase` を v14 にし、`sync_remote_progress` と `sync_own_progress` に `url TEXT` と `title TEXT` を加える移行を書く。既存の行が残って両列が NULL になることと、新規作成でも列があることを、移行テスト（`novel_database_migration_v14_test.dart`。v13 のテストに倣う）で確かめる（design D4）
- [ ] 2.2 `ProgressSyncRepository` の行の読み書き（`_recordToRow` / `_rowToRecord`）で `url` と `title` を扱い、受け取った記録を全件返す問い合わせを加える。`replaceRemote` / `replaceOwn` / `commitOwn` / `upsertOwn` でURLとタイトルが保存されて読み戻せることと、全件の問い合わせが全端末の記録を返すことを、リポジトリのテストで確かめる

## 3. 送信へのURLとタイトルの付与（service）

- [ ] 3.1 送信側に「送ってよい小説とそのURL・タイトル」を返す読み込みを加え、`ProgressSyncService` から `buildOwnRecords` に渡す。適用側の `loadSyncableNovelIds` と、汎用 Web を除く規則を共有する（design D3）。サービスのテストで次の2点を確かめる
  - URLが無い `sync_own_progress` の状態から送信すると、位置が動いていなくても、URLとタイトル付きの記録がアップロードされる
  - その後、何も変えずに送信してもアップロードされない
- [ ] 3.2 古い形式の記録（URL無し）を受け取っても、フォルダに入ったときの適用（自動適用と確認）が従来どおり動くことを、既存の適用のテストに1件加えて確かめる（仕様「作品URLの無い記録も読める」）

## 4. 一覧の組み立て

- [ ] 4.1 `progress_sync/domain/` に、受け取った記録・登録済みフォルダ名の集合・URL判定関数から一覧の行を作る純粋な関数を加える（design D5）。次の3点を単体テストで確かめる（仕様「一覧に出す小説」の各シナリオ）
  - 登録済みの小説、URLが無い記録、判定に通らない記録を除く
  - 小説ごとに `read_at` が最も新しい1件にまとめる
  - 新しい順に並べる
- [ ] 4.2 作品URLが記録の小説を指しているかを判定する関数を加える。`NovelSiteRegistry` で汎用 Web 以外のサイトを見つけ、`DownloadService.buildFolderName` と同じ規則（必要ならその規則を共有できる場所へ切り出す）で作ったフォルダ名と比べる。次の2点を単体テストで確かめる（design D5）
  - なろう・なろう R18・カクヨム・ハーメルン・青空文庫の、正しいURLは通る
  - 別の作品のURL、汎用 Web のURL、対応していないURLは通らない
- [ ] 4.3 一覧のプロバイダを加える。同期を使えない場合とログインしていない場合は、表を読まずに空の一覧を返す。取得の通知で作り直し、`allNovelsProvider` の更新で登録済みになった小説が消える（design D6）。プロバイダのテストで、この3点と、Drive への通信が起きないことを確かめる

## 5. ダウンロードダイアログの一覧

- [ ] 5.1 en / ja / zh の `.arb` に一覧の文言（見出し、「すべて表示（N）」、端末名・話の番号・日時の行表記）を加え、`fvm flutter gen-l10n` が通ることを確かめる（仕様「文言の多言語化」）
- [ ] 5.2 `download_dialog.dart` に一覧の欄を加える（design D7）。ウィジェットテストで次の4点を確かめる
  - 一覧が空のとき、ログインしていないとき、同期が無効なときは欄が無い
  - 新しい順に最初の5件と「すべて表示（N）」が出て、押すと全件になる
  - 5件以下なら「すべて表示」が無い
  - タイトルが無い行は作品URLを示す
- [ ] 5.3 行を選ぶとURL欄に入り、ダウンロードは始まらないこと、ダウンロード中は選べないことを、ウィジェットテストで確かめる（仕様「選んだ小説のURLを入力欄に入れる」）
- [ ] 5.4 件数が多くても、一覧の高さの上限でダイアログが画面からはみ出さないことを、iPhone の縦向き相当の画面サイズのウィジェットテストで確かめる（仕様「一覧の表示」）
