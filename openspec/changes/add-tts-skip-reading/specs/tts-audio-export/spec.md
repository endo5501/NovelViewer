## MODIFIED Requirements

### Requirement: WAVセグメントのPCM連結
エクスポート時、システムはDBから対象エピソードの全セグメントを `segment_index` 順に取得し、各セグメントのWAV BLOBから44バイトのヘッダをスキップしてPCMデータを抽出し、連結しなければならない（SHALL）。

`skip = 1` のセグメントは、WAV BLOBを保持していても連結対象から除外しなければならない（SHALL）。スキップ指定は音声データを削除しないため、音声の有無のみで対象を判定してはならない（MUST NOT）— 除外を怠ると、ユーザーが読み上げ対象から外したはずの文がMP3に混入し、エラーにならないまま気付かれない。

#### Scenario: 複数セグメントのPCMデータが正しい順序で連結される
- **WHEN** エピソードに3つのセグメント（index 0, 1, 2）が存在する
- **THEN** セグメント0、1、2の順にPCMデータが連結される
- **AND** 各セグメントのWAVヘッダ（先頭44バイト）は連結データに含まれない

#### Scenario: セグメントが1つのみの場合
- **WHEN** エピソードにセグメントが1つのみ存在する
- **THEN** そのセグメントのPCMデータ（WAVヘッダを除く）がそのままエンコードに渡される

#### Scenario: スキップ指定のセグメントが連結されない
- **WHEN** エピソードに3つのセグメント（index 0, 1, 2）が存在し、いずれも音声を保持しており、index 1 が `skip = 1` である
- **THEN** セグメント0、2の順にPCMデータが連結され、セグメント1のPCMデータは含まれない

#### Scenario: スキップ以外に音声が無い場合はエクスポートできない
- **WHEN** 音声を保持するセグメントがすべて `skip = 1` である状態でエクスポートを実行する
- **THEN** 連結対象が空となり、エクスポートする音声データが無い旨のエラーが通知される
