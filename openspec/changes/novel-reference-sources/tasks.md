## 3. `novel_data.db` v3 とスナップショットの参照元

- [x] 3.1 `novel_data.db` v2→v3 で `word_summaries` を作り直し、`reference_sources` 列を加える（一時テーブル→コピー→削除→改名→インデックス）。全行が保持されること、`fact_cache`/`bookmarks` に触れないこと、新規作成とスキーマが一致すること、v8→v9 の移送が v3 を刻むことを、テストで確認する

## 4. パイプライン：祖先ごとの圧縮とラベル付き合流

- [x] 4.1 プロンプトビルダーで、集約プロンプトに `preserveSourceLabels`、最終要約プロンプトに `hasReferenceSources` のフラグを加える。フラグが偽のときは現行と文字列が一致し、真のときはラベル保持、本作優先の3点の指示が入ることを、テストで確認する
- [x] 4.2 `_extractFactsRecursive` が、終了の閾値と開始の depth を引数に取り、使い終えた depth を返せるようにする。既存の呼び出しの挙動が変わらないことを、既存のパイプラインのテストで確認する
- [x] 4.3 `summarizeFromSources` を実装する。次の点を、フェイククライアントを使ったテストで確認する
  - 祖先ごとの圧縮。`maxResponseSize` 内なら LLM を呼ばない
  - 祖先の事実の各行に「『title』より:」ラベルが付き、D3 の順で本作の事実の前に並ぶ
  - 切り詰めは末尾（本作の事実）を残し、先頭（祖先の行）から削る
  - 周回番号が祖先の圧縮と合流後の集約を通して単調に増える
  - 全出典で事実が無いときだけ「事実なし」で失敗する
  - 祖先が空なら `summarizeFromFacts` と同じ呼び出しの並びになることも、テストで固定する
