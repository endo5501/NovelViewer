# Spec Delta

## ADDED Requirements

### Requirement: 辞書ダイアログ追加フォームの幅に応じたレイアウト

辞書ダイアログの追加フォーム（「表記」入力欄、「読み」入力欄、「読み上げしない」チェックボックス、追加ボタン）は、フォームに与えられた幅に応じてレイアウトを切り替えなければならない (MUST)。

- 広い幅（デスクトップおよびiPadでの辞書ダイアログの内容幅を含む）では、4つの部品を1行に並べる従来のレイアウトを維持しなければならない (MUST)。
- 狭い幅（iPhone縦向きでの辞書ダイアログの内容幅を含む）では、「表記」入力欄と「読み」入力欄をそれぞれフォームの全幅を使う別の行に置き、「読み上げしない」チェックボックスと追加ボタンをその下に置かなければならない (MUST)。

ソフトウェアキーボードの表示などでダイアログの高さが縮んだ場合でも、ダイアログの内容はレイアウトのオーバーフローを起こしてはならない (MUST NOT)。また、追加フォームの各入力欄に操作で到達できなければならない (MUST)。

レイアウトの切り替えをまたいでも、入力途中の「表記」「読み」の内容は失われてはならない (MUST NOT)。

#### Scenario: 狭い幅では表記欄と読み欄が縦に並ぶ

- **WHEN** iPhone縦向き相当の画面（例: 393×852）で辞書ダイアログを開く
- **THEN** 「読み」入力欄は「表記」入力欄の下に置かれ、両方の入力欄がフォームのほぼ全幅を使って表示される

#### Scenario: 狭い幅でもチェックボックスと追加ボタンが使える

- **WHEN** iPhone縦向き相当の画面で、表記を入力し「読み上げしない」にチェックを入れて追加ボタンを押す
- **THEN** 読みが空のエントリが追加され、一覧に表示される（既存の「読み上げなし辞書エントリ」の挙動と同一）

#### Scenario: 広い幅では1行レイアウトが維持される

- **WHEN** デスクトップ相当の画面（例: 800×600）で辞書ダイアログを開く
- **THEN** 「表記」入力欄、「読み」入力欄、「読み上げしない」チェックボックス、追加ボタンが同じ1行に並ぶ

#### Scenario: キーボード表示中でもオーバーフローしない

- **WHEN** iPhone縦向き相当の画面（393×852、および小型機相当の 375×667）で、ソフトウェアキーボードが画面下部を占めている状態で辞書ダイアログを表示する
- **THEN** レイアウトのオーバーフローは発生せず、「表記」入力欄と「読み」入力欄の双方に操作で到達できる

#### Scenario: エントリが多くキーボード表示中でもオーバーフローしない

- **WHEN** 辞書に多数のエントリがある状態で、iPhone縦向き相当の画面にソフトウェアキーボードが表示されている
- **THEN** レイアウトのオーバーフローは発生せず、追加フォームとエントリ一覧はスクロールで閲覧できる

#### Scenario: レイアウトが切り替わっても入力内容が残る

- **WHEN** 「表記」と「読み」に入力した後、画面幅が変わって追加フォームのレイアウトが1行と縦並びの間で切り替わる
- **THEN** 「表記」と「読み」の入力内容はそのまま残っている
