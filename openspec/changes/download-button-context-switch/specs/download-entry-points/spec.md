## Purpose

アプリ内のどこからダウンロードを開始できるか、そして各入口が「新規ダウンロード」と「表示中の小説の更新」のどちらを意味するかを定める。ファイルブラウザが `Drawer` に収まり、本文表示とライブラリ操作が画面上で排他になったことを前提に、読者が今いる文脈でもっとも必要とするダウンロード操作をボタンに割り当てる。

## ADDED Requirements

### Requirement: AppBar のダウンロードボタンは文脈で意味が切り替わる

AppBar のダウンロードボタンは、更新対象が解決できるかどうかによって、2つの意味のいずれかを持たなければならない（SHALL）。

- 更新対象が解決できる場合、ボタンは**更新**を意味しなければならない（SHALL）。押下により、その小説の差分ダウンロードが開始される。
- 更新対象が解決できない場合、ボタンは**新規ダウンロード**を意味しなければならない（SHALL）。押下により、新規ダウンロードダイアログが表示される。

ボタンのアイコンとツールチップは、そのときの意味と一致していなければならない（SHALL）。2つの意味が同一のアイコン・同一のツールチップで提示されてはならない（SHALL NOT）。

ボタンは、いずれの意味においても無効化されてはならない（SHALL NOT）。どちらの状態でも押下は有効な操作である。

#### Scenario: 更新可能な小説を読んでいるときは更新ボタンになる

- **WHEN** テキストビューアが、登録済み小説フォルダに属するエピソードを表示している
- **THEN** AppBar のボタンは更新を表すアイコンとツールチップで表示され、押下するとその小説の更新が開始される

#### Scenario: ファイル未選択のときは新規ダウンロードボタンになる

- **WHEN** テキストビューアがファイルを表示していない
- **THEN** AppBar のボタンはダウンロードを表すアイコンとツールチップで表示され、押下すると新規ダウンロードダイアログが表示される

#### Scenario: 2つの状態は見た目で区別できる

- **WHEN** 更新可能な小説を表示している状態と、ファイル未選択の状態のボタンを比較する
- **THEN** アイコンとツールチップの双方が異なる

#### Scenario: 更新の完了後も更新ボタンのままである

- **WHEN** AppBar のボタンから更新を実行し、それが完了して進捗ダイアログを閉じる
- **THEN** 同じエピソードが表示されたままであり、ボタンは引き続き更新を意味する

### Requirement: 更新対象は表示中のファイルから解決される

更新対象は、テキストビューアが現在**表示しているファイル**から解決されなければならない（SHALL）。ファイルブラウザが現在表示しているディレクトリから解決してはならない（SHALL NOT）。ファイルブラウザは `Drawer` の中で本文とは独立に移動できるため、現在地は読者が読んでいる小説を表さない。

解決は、表示中のファイルのパスから、**最も近い登録済み小説フォルダ**を辿る既存の共有ルールに従わなければならない（SHALL）。これにより、整理用サブフォルダに何段入れ子になっていても対象が定まる。解決された小説フォルダのフォルダ名と、その親ディレクトリが更新に渡される。

次のいずれかに該当する場合、更新対象は解決できないものとして扱われなければならない（SHALL）。

- 表示中のファイルが無い
- 表示中のファイルのパス上に、登録済み小説フォルダが1つも無い
- 解決された小説が Web 記事コレクションである（コレクションは一括再取得の対象ではなく、記事ごとにダウンロードされる）

#### Scenario: 入れ子になった小説も解決される

- **WHEN** 整理用サブフォルダ内にある登録済み小説フォルダのエピソードを表示している
- **THEN** 更新対象としてその小説フォルダが解決され、更新はそのサブフォルダ内の元の位置へ書き戻される

#### Scenario: ファイルブラウザの現在地は更新対象を変えない

- **WHEN** ある小説のエピソードを表示したまま、ファイルブラウザでライブラリルートや別の小説フォルダへ移動する
- **THEN** AppBar のボタンは表示中のエピソードが属する小説を対象とし続け、ファイルブラウザの現在地にあるものを対象としない

#### Scenario: 未登録フォルダのファイルは更新対象にならない

- **WHEN** 登録済み小説フォルダに属さないテキストファイルを表示している
- **THEN** 更新対象は解決されず、AppBar のボタンは新規ダウンロードを意味する

#### Scenario: Web 記事コレクションは更新対象にならない

- **WHEN** Web 記事コレクションのエピソードを表示している
- **THEN** 更新対象は解決されず、AppBar のボタンは新規ダウンロードを意味する。「コレクションは一括更新できません」というエラーがこの入口から提示されることはない

### Requirement: ファイルブラウザから新規ダウンロードを開始できる

ファイルブラウザのツールバーは、新規ダウンロードダイアログを開くボタンを備えなければならない（SHALL）。ファイルブラウザは `Drawer` として AppBar の上に重なるため、ライブラリを操作している間、AppBar のボタンには手が届かない。このボタンは、その間の新規ダウンロードの入口である。

ボタンは、ファイルブラウザがライブラリ内のどのディレクトリを表示していても利用できなければならない（SHALL）。押下によって開かれるダイアログの挙動（保存先の選択、既定の保存先、コレクションの取り扱い）は、AppBar から開いた場合と同一でなければならない（SHALL）。

#### Scenario: ツールバーから新規ダウンロードダイアログを開く

- **WHEN** ユーザーがファイルブラウザのツールバーのダウンロードボタンを押す
- **THEN** 新規ダウンロードダイアログが表示される

#### Scenario: ライブラリルート以外でも利用できる

- **WHEN** ファイルブラウザが整理用サブフォルダや小説フォルダを表示している状態でダウンロードボタンを押す
- **THEN** 新規ダウンロードダイアログが表示される

#### Scenario: どちらの入口からでもダイアログは同一である

- **WHEN** ファイルブラウザのツールバーから開いたダイアログと、AppBar から開いたダイアログを比較する
- **THEN** 保存先の選択肢と既定値、および提示される入力項目は同一である

### Requirement: 既存のダウンロード入口は維持される

この変更は、既存の入口を取り除いてはならない（SHALL NOT）。

- 小説フォルダの右クリックメニューの「更新」は維持されなければならない（SHALL）。これは、今読んでいない小説を更新する唯一の手段である。
- アプリ外部から届くダウンロード要求（カスタム URL スキーム経由）の扱いは変更されてはならない（SHALL NOT）。従来どおり、URL が入力済みのダイアログとして提示され、確認を経ずにダウンロードが始まることはない。

#### Scenario: 右クリックの更新は残る

- **WHEN** ユーザーが、今表示していない小説フォルダを右クリックする
- **THEN** コンテキストメニューには従来どおり「更新」が表示され、選択するとその小説の更新が開始される

#### Scenario: 外部からのダウンロード要求は変わらない

- **WHEN** アプリ外部からダウンロード要求 URL が届く
- **THEN** AppBar のボタンがそのとき何を意味していたかにかかわらず、URL が入力済みのダウンロードダイアログが表示される

### Requirement: 新規の表示文字列は3言語で提供される

この変更で新たに導入されるユーザー可視の文字列（AppBar の更新ツールチップ、ファイルブラウザのダウンロードボタンのツールチップ）は、en / ja / zh の `.arb` にすべて存在しなければならない（SHALL）。

#### Scenario: 3言語のパリティ

- **WHEN** アプリを en / ja / zh 向けにビルドする
- **THEN** 新規文字列は3つの `.arb` すべてに存在し、`gen-l10n` は未翻訳の警告を出さない
