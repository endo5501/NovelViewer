## Why

小説サイトの更新を取り込む操作が、現状ではファイルブラウザで対象の小説フォルダを右クリックし、メニューから「更新」を選ぶ、という手順を踏む。読者が日常的にもっとも多く行う操作であるにもかかわらず、もっとも手数が多い。

一方 AppBar のダウンロードボタンは、何を読んでいようと常に「新規ダウンロードダイアログを開く」だけで、読書中にはほぼ押されない。

直前の変更でファイルブラウザが `Drawer` に統一され、本文表示とファイルブラウザは画面上で排他になった。Drawer は AppBar の上に重なるため、「Drawer を開いている＝ライブラリを操作している」「Drawer を閉じている＝本文を読んでいる」という2つの文脈が、はじめて明確に分離した。この分離を使って、それぞれの文脈で意味のあるダウンロード操作をボタンに割り当てる。

## What Changes

- AppBar のダウンロードボタンを、**状態によって意味の変わる1つのボタン**にする。
  - 更新可能な小説の本文を表示中 → アイコンは「更新」、押すとその小説を差分ダウンロード（現在の右クリック「更新」と同じ処理）
  - それ以外（ファイル未選択 / 未登録フォルダのファイル / Web コレクション） → アイコンは「ダウンロード」、押すと従来どおり新規ダウンロードダイアログ
  - アイコンとツールチップを状態と一緒に切り替えるため、ボタンは押す前に何が起きるかを示す。
- ファイルブラウザ（Drawer）のツールバーに**新規ダウンロードボタンを新設**する。Drawer は AppBar を覆うため、ライブラリ操作中はこれが新規ダウンロードの入口になる。
- 右クリックの「更新」は**維持**する。今読んでいない小説を更新する唯一の手段であるため。
- 更新の進捗ダイアログに**キャンセルボタンを追加**する。更新がワンタップで走るようになるため、誤操作を止める手段が必要になる。既存の `DownloadNotifier.cancel()` とダウンロードダイアログのキャンセル UI に揃える。
- 更新対象の解決には、既存の共有ルール `resolveNovelFolderPath`（最も近い登録済み小説フォルダを返す）を使う。入れ子の深さに依存せず、`null` が返る条件がそのまま「更新できない」条件に一致する。

### 非目標

- **Web コレクションへの記事追加を「更新」として扱うこと**。コレクションはダウンロードダイアログでの「既存コレクションに追加」で従来どおり扱う。ダイアログのコレクション選択 UI は URL 入力後にしか現れないため、事前選択した状態で開く導線はダイアログの状態機械に手を入れる必要があり、独立した変更に値する。
- **Drawer のダウンロードボタンで保存先をブラウザの現在地に初期選択すること**。`text-download` の「保存先の既定はライブラリルート」という要件を変えることになるため、今回は据え置く。
- **AppBar タイトルの表示元の是正**。`selectedNovelTitleProvider` が `currentDirectoryProvider`（ファイルブラウザの現在地）を見ているため、読書中に Drawer でライブラリルートまで上がるとタイトルが `NovelViewer` に戻る。Drawer 化が露出させた既存の症状であり、本変更で新たに生じるものではない。エピソード進捗 `(N/M)` の意味づけを決め直す必要があるため、別の変更として扱う。
- **キーボードショートカットの割り当て**。

## Capabilities

### New Capabilities

- `download-entry-points`: ダウンロードを開始できる入口と、各入口が何を意味するか。AppBar のボタンが状態に応じて「更新」と「新規ダウンロード」のどちらとして振る舞うか、その判定規則、およびファイルブラウザのツールバーに置かれる新規ダウンロードボタン。

### Modified Capabilities

- `novel-refresh`: 更新のトリガーがコンテキストメニューだけでなく AppBar のボタンからも来るようになる。進捗ダイアログに、ダウンロード中のキャンセルアクションを追加する。

## Impact

- `lib/home_screen.dart` — AppBar のダウンロードボタン（`:566`）を状態依存に。更新の起動と進捗ダイアログの表示を追加。
- `lib/features/file_browser/presentation/file_browser_panel.dart` — `_buildToolbar`（`:208`）に新規ダウンロードボタンを追加。`_RefreshProgressDialog`（`:822`）は AppBar からも使うため共有可能な場所へ切り出し、キャンセルボタンを追加。`_startRefresh`（`:656`）の共通化。
- 新規プロバイダ — `selectedFileProvider` / `libraryPathProvider` / `allNovelsProvider` から更新対象（フォルダ名と親ディレクトリ）を導出する。`resolveNovelFolderPath` を利用し、Web コレクションを除外する。
- `lib/features/text_download/presentation/download_dialog.dart` — ダウンロードダイアログの開閉状態を provider に持たせ、全入口が通る `showDownloadDialog` を追加。`home_screen.dart` が私有していた開閉フラグはここへ移る。Drawer の入口がそれを迂回すると、外部から届いた要求が2枚目のダイアログを積むため。
- `lib/features/text_download/providers/text_download_providers.dart` — `DownloadNotifier` に、トークン生成前に届いたキャンセル要求を保持する仕組みを追加。`refreshNovel` は自身を downloading と報告してから小説URLを参照するため、その間のキャンセルが落ちる。
- `lib/features/file_browser/presentation/file_browser_panel.dart`（移動処理） — 小説フォルダの移動時に、表示中エピソードの選択パスを移動後の位置へ付け替える。更新対象は表示中ファイルのパスから解決されるため、付け替えないと次の更新が移動前の場所へ重複フォルダを作る。
- `lib/l10n/*.arb` — 更新ボタンのツールチップ、Drawer のダウンロードボタンのツールチップ。en/ja/zh の3言語。キャンセル関連の文字列は既存のものを再利用する。
- `DownloadService`（ダウンロード処理そのもの）と `refreshNovel` の署名・保存先解決・差分判定には変更を加えない。
