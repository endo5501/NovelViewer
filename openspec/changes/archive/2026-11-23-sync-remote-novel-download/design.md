# Design

## Context

- 同期の記録は端末ごとに1つの `device-<id>.json` で、小説ごとに `episode`、`file_name`、`body_offset`、`body_hash`、`read_at` を持つ（`device_progress_codec.dart`、`format: 1`）。デコーダは知らない項目を読み飛ばし、`format` が違うファイルは受け付けない。
- 取得した記録は `sync_remote_progress` に、端末と小説の組ごとに保存される。この端末にまだ無い小説の記録も保存されている（`ProgressSyncRepository.replaceRemote`）。
- 送信は、`buildOwnRecords` で組み立てた記録が `sync_own_progress`（前回送った内容）と同じなら行わない（`ProgressSyncService._push` の `_sameRecords`）。比較には `SyncProgressRecord` の等値性を使う。
- 小説フォルダ名は `<siteType>_<サイト上のID>` で、`DownloadService.buildFolderName` が正規化済みのURLから作る。`novels` テーブルは、ダウンロード時の作品URL（`url`）とタイトル（`title`。`novel-rename-title` で変わる）を持つ。
- 新規ダウンロードダイアログ（`download_dialog.dart`）には、URL欄、保存先の選択、汎用 Web 記事のコレクション指定があり、URLを受け付けるのは `idle` と `error` の状態のとき（`_acceptsInput`）。
- データベースは現在 v13。

## Goals / Non-Goals

**Goals:**

- 記録に作品URLとタイトルを、古いビルドと互換のまま加える。
- 一覧は、すでに保持している記録とこの端末の登録済み小説だけから作る。

**Non-Goals:**

- 一覧からまとめてダウンロードすること。ダイアログは1回に1作品のまま。
- この端末で削除した小説を一覧から隠すこと（必要になったら `sync_handled` と同じ考え方で、行ごとの非表示を後から加える）。
- タイトルでの絞り込み。
- 記録の無い小説（他の端末でダウンロードしただけで開いていない小説）を出すこと。

## Decisions

### D1. `format` は 1 のまま、`url` と `title` を任意の項目として加える

各小説の記録に `"url"` と `"title"` を加える。どちらも、無い、または `null` でもよい。

- 代案: `format` を 2 に上げる。古いビルドは版の違うファイルを受け付けないので、端末の一部を更新した時点で、古いビルドは新しいビルドの記録をすべて受け取れなくなる。今回の追加は、知らない項目を読み飛ばす今のデコーダで読めるため、版を上げる理由が無い。
- デコードでは、`url` と `title` が文字列でも `null` でも無くてもよいことにする。数値など他の型が入っているときは、今の方針（型が違えば `FormatException`）に合わせ、そのファイルを不正として扱う。

### D2. `SyncProgressRecord` に `url` と `title` を持たせ、等値性に含める

`SyncProgressRecord` に `String? url` と `String? title` を加え、`==` と `hashCode` に含める。

- これで、`_sameRecords` による送信の省略と、`commitOwn` の「途中で変わった行は上書きしない」の判定が、そのままURLとタイトルも見るようになる。更新後の最初の送信では、`sync_own_progress` の行にURLが無いので違う内容と判定され、送り直しになる（仕様「更新後の最初の同期で送り直す」）。
- 代案: 比較の関数だけでURLとタイトルを見る。等値性を使う箇所（`commitOwn` の `expected` の比較など）と判定が食い違うので採らない。
- `buildOwnRecord` の「位置が動いていなければ `read_at` を引き継ぐ」判定は、これまでどおり位置だけを見る。URLやタイトルが変わっても `read_at` は進まない。

### D3. 送る記録のURLとタイトルは `novels` テーブルから取る

`ProgressSyncService` は、送信のたびに登録済みの小説（`novels` の `folder_name`、`url`、`title`）を読み、`buildOwnRecords` に渡す。`buildOwnRecords` は小説ごとにURLとタイトルを付ける。

- 送信側の `syncableNovelIds`（`loadSyncableNovelIds`。受け取った記録の適用でも使っている）は、すでに登録済みの小説を読んでいる。送信側だけは、これを「送ってよい小説とそのURL・タイトル」を返す関数に置き換え、読み込みを1回で済ませる。適用側は小説の集合だけを使い続ける。汎用 Web コレクションを除く規則は、両方で同じ関数を使って共有する。
- 他の端末から適用した記録（`upsertOwn`）は、受け取った記録のURLとタイトルを持つ。次の送信でこの端末の `novels` の値に置き換わり、違っていれば送り直しになる。この送り直しで `read_at` は進まない（D2）ので、受け取った記録の時刻が保たれる。

### D4. データベースを v14 にし、2つの表に列を加える

`sync_remote_progress` と `sync_own_progress` に、`url TEXT` と `title TEXT`（どちらも NULL 可）を加える。移行は `ALTER TABLE ... ADD COLUMN` だけで、既存の行はどちらも NULL になる。

- `sync_own_progress` の既存の行が NULL になることが、D2 による送り直しのきっかけになる。
- `sync_handled` は変えない。

### D5. 一覧は、受け取った記録と登録済み小説から作る純粋な関数で決める

一覧に出す行は、次を入力とする純粋な関数（`progress_sync/domain/` に置く）で決める。

- 受け取った記録（`RemoteProgress` の一覧）
- この端末の登録済み小説のフォルダ名の集合
- 作品URLが記録の小説を指しているかを判定する関数

関数は、登録済みの小説と、URLが無い記録、判定に通らない記録を除く。残った記録を小説ごとに `read_at` の最も新しい1件にまとめ、新しい順に並べて返す。

判定関数は、`NovelSiteRegistry.findSite` で汎用 Web 以外のサイトが見つかり、そのサイトで正規化したURLから作ったフォルダ名が記録の小説と一致する場合だけ通す。フォルダ名を作る処理は `DownloadService.buildFolderName` と同じものを使い、規則を2か所に持たない。

- この判定を入れる理由は、記録が持っているURLを、ダウンロードするURLとしてそのまま使うためである。記録と別の小説を指すURLを通すと、ダウンロードした小説が一覧から消えず、他の端末の位置も適用されない。汎用 Web のURLを通すと、同期しない種類の小説を一覧から作ってしまう。
- 代案: フォルダ名からURLを組み立てる。青空文庫は組み立てられず、なろうはホストが決まらないので採らない（proposal「Why」）。

### D6. 一覧のプロバイダと、取得のたびの更新

`ProgressSyncRepository` に、受け取った記録を全件読む問い合わせを加える。一覧のプロバイダ（`FutureProvider`）は、次の値から D5 の関数で一覧を作る。

- 同期を使えるか（`progressSyncAvailableProvider`）
- ログインの状態（`syncAccountStateProvider`）
- 登録済みの小説（`allNovelsProvider`）
- 受け取った記録

使えない場合やログインしていない場合は、表を読まずに空の一覧を返す。取得のたびに一覧を作り直すため、`progressSyncPulledProvider` の通知で無効化する。ダウンロードが完了すると `allNovelsProvider` が更新されるので、ダウンロードした小説は一覧から自然に消える。

Drive への問い合わせはしない。ダイアログを開いたときに最新の記録を取りに行くと、仕様の「一覧を出すために通信しない」に反する。また、URLの入力を待たせてしまう。

### D7. ダイアログでの表示

- 一覧の欄は、URL欄と保存先の下に置く。一覧が空のときは欄ごと出さない（仕様「一覧を出さない条件」）。
- 最初は5件で、6件以上なら「すべて表示（N）」を出す。開いた状態は、ダイアログを閉じるまで保つ。一覧の高さに上限を設けて中をスクロールさせる。この上限は iPhone の縦向きでも、URL欄と開始ボタンが画面に収まる値にする。
- 行を選ぶと、外部から届いたURLと同じ経路でURL欄に入れ、`_urlError` を消す。`_acceptsInput` が偽の間は行を選べないようにする。
- 日時は、`sync_prompt_host.dart` の確認で使っている表記に合わせる。

## Risks / Trade-offs

- [他の端末が古いビルドのままだと一覧に出ない] → 仕様どおり出さない。`docs/progress-sync.md` に「両方の端末を更新すると出る」と書く。
- [記録が消えないので、一覧が少しずつ長くなる] → 新しい順に並べて最初は5件にし、高さの上限でダイアログが伸びないようにする。読み終えた小説を隠す操作は後から加えられる（Non-Goals）。
- [送信の内容が増える] → 1作品あたりURLとタイトルの分だけ増える。数百作品でも数十KBほどで、送るのは内容が変わったときだけである。
- [v14 にすると、v13 までのビルドではこのデータベースを開けない] → これまでの版上げと同じ扱い。main ブランチを v14 にそろえてから配る。
- [タイトルの変更が他の端末に届くまでの間、古いタイトルで出る] → 次の送信と取得で直る。表示だけの問題なので許容する。

## Migration Plan

1. v14 の移行で列を加える（既存の行は NULL）。
2. 新しいビルドの最初の送信で、すべての記録がURLとタイトル付きで送り直される。`read_at` は変わらないので、他の端末で余計な確認は出ない。
3. 戻す場合は、Drive 上の記録はそのまま古いビルドで読める。データベースは v14 のままで、古いビルドでは開けないため、戻すには v13 のバックアップが要る。
