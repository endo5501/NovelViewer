# Proposal

## Why

読書進捗の同期（`reading-progress-sync`）で、別の端末で読み進めた小説を続きの位置から開けるようになった。しかし、その小説をこの端末でまだダウンロードしていなければ、続きを読むには、作品のURLを自分で探して新規ダウンロードダイアログに入力する必要がある。

この端末は、まだダウンロードしていない小説の記録もすでに受け取って保持している。それでも一覧から選べないのは、記録に小説を特定する `novelId`（フォルダ名）しか無く、タイトルとURLが無いためである。フォルダ名からURLを作れないサイトもある（青空文庫は作家番号が要る。なろうは `ncode` と `novel18` のどちらのホストか判別できない）。

## What Changes

- 同期で送る小説ごとの記録に、任意の項目として「作品URL」と「タイトル」を加える。値は送る側の端末の `novels` テーブルから取る。記録の形式の版（`format`）は 1 のまま変えないので、古いビルドとも互いに記録を読める。
- 「前回送った内容と同じなら送らない」の比較に、URLとタイトルも含める。このため、新しいビルドに更新した後の最初の同期では、読む位置が動いていなくても、URLとタイトルを付けた記録が送り直される。古いビルドでダウンロードした小説も、この時点から一覧に出るようになる。
- 新規ダウンロードダイアログに「他の端末で読んでいる小説」の一覧を加える。出すのは、他の端末から受け取った記録のうち、この端末に無く、URLが付いている小説である。
  - 1作品1行にまとめ、いちばん新しく読んだ端末の記録を使う。行には、タイトル、端末名、話の番号、読んだ日時を出す。
  - 読んだ日時の新しい順に並べる。最初は5件まで出し、残りは「すべて表示」で開く。開いた一覧は、高さを決めた枠の中でスクロールする。
  - 行を選ぶとURL欄にURLが入る。ダウンロードは、これまでどおり開始ボタンを押して始める。
  - 同期が無効なビルドやログインしていないとき、および出す小説が無いときは、一覧の欄を出さない。
- ダウンロードした小説を初めて開いたときに他の端末の位置から開く動作は、既存の規則（この端末に進捗が無い小説への自動適用）のままとし、変更しない。
- この端末で削除した小説を一覧から隠す操作は、今回は加えない。

## Capabilities

### New Capabilities

- `remote-novel-download`: 新規ダウンロードダイアログで、他の端末で読んでいて、この端末にまだ無い小説を一覧にし、選んでダウンロードできるようにする。

### Modified Capabilities

- `reading-progress-sync`: 送る記録の内容に作品URLとタイトルを任意の項目として加える。前回と同じ内容かどうかの判定に、この2項目を含める。

## Impact

- `lib/features/progress_sync/domain/`: `SyncProgressRecord`、記録の読み書き（`device_progress_codec.dart`）、送る記録の組み立て（`sync_rules.dart`）。
- `lib/features/progress_sync/data/`: `ProgressSyncRepository`（受け取った記録と送った記録の保存、一覧を作る問い合わせ）、`ProgressSyncService`（送る記録にURLとタイトルを付ける）。
- `lib/features/novel_metadata_db/data/novel_database.dart`: スキーマを v14 に上げ、`sync_remote_progress` と `sync_own_progress` に `url` と `title` の列を加える。
- `lib/features/text_download/presentation/download_dialog.dart`: 一覧の欄を加える。
- `lib/l10n/`: en / ja / zh の `.arb` に新しい文言を加える。
- `docs/progress-sync.md`: 同期するもの、他の端末の小説のダウンロードについて書き加える。
- 互換性: v14 のデータベースは、v13 までのビルドでは開けない。Drive 上の記録ファイルの形式は互換のまま。
