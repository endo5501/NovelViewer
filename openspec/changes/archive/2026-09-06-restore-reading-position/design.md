## Context

`ReadingProgress`とRepositoryは小説ごとに`file_name`と`updated_at`を保存する。`readingProgressAutoSaveListenerProvider`は選択時に行を置換し、`readingProgressAutoOpenListenerProvider`はフォルダ再入場時に話を選択する。起動時はライブラリルートを開く。

横書きの`currentViewLineProvider`への報告はスクロール量と推定行高から求められており、折り返しを含む精密な復元には使えない。縦書きにはページごとの位置情報があるが、ルーン単位のレイアウトとDartのUTF-16文字列座標の区別が必要。横書きのルビは`WidgetSpan`一つとして数えられる。`episode-navigation`は次話を冒頭、前話を末尾から開くワンショットintentを持つ。

## Goals / Non-Goals

**Goals:**

- Windows・macOSと将来のiOSで共有する、小説ごとの最終読書位置と起動時復元。
- レイアウト変更に耐える位置表現、明示操作を優先する復元、非同期保存の順序保証。
- 既存DB、しおり、検索、話移動、TTS追従の互換性維持。

**Non-Goals:**

- iOSのビルド・配布・専用画面、端末間同期、話ごとの全履歴。
- 改稿前後の同一文章を探すあいまい照合、ピクセル単位の画面再現。
- しおりの座標形式変更、TTS座標系の全面改修。

## Decisions

### 1. 本文のUTF-16オフセットを共通座標にする

`parseRubyText`のPlainTextSegment.textとRubyTextSegment.baseを連結した文字列を基準とする。改行は読み込み・パース後の値を保持し、読み仮名とルビタグは含めない。位置は0始まりのUTF-16コード単位。結合文字やサロゲートペアの途中は直前の表示文字境界へ補正し、ルビ内部は必要に応じ親文字の先頭へ寄せる。

横書きは実際の描画と同じ幅・スタイル・ルビ寸法で表示上端の本文位置を求め、display offsetと共通座標を変換する。縦書きはページ先頭の原文位置を、ルーン数や装飾用文字から推測せずパース結果との対応表で求める。ページ番号・推定行番号・スクロール比率の保存は表示条件で変動するため採用しない。変換と計測は既存ヘルパーを利用し、必要な部分だけ拡張する。

### 2. 既存のグローバル履歴を拡張する

現行v9の`novel_metadata.db`をv10へ移行し、`reading_progress`へ`body_offset INTEGER NOT NULL DEFAULT 0`と`body_hash TEXT NULL`を追加する。ハッシュは上記本文文字列のSHA-256とし、内容単位にキャッシュする。`novel_id`と`file_name`の識別方法と一小説一行は維持する。

位置指定なしで同じ話を選択しても保存済み位置を0に上書きしない。別の話を選択した場合は新しい話の位置0・ハッシュ未設定として更新し、実際の表示位置確定後に保存する。復元用履歴の取得はこの更新より先に行う。Repositoryに位置を扱う操作を追加し、既存の話選択APIの互換性を保つ。単なる位置更新では進捗バッジ用revisionを毎回増加させない。

起動用の対象は履歴の`updated_at DESC, novel_id ASC`の先頭一件から選ぶ。別ストアの最後の小説IDとの二重書き込みを避ける。定期タイマーは未変更の小説や非表示の小説の日時を更新しない。

### 3. 保存の対象と順序を固定する

アプリ寿命の読書位置コーディネーターをProviderで保持する。表示からは小説ID・ファイル名・コンテンツ世代・選択世代を伴うスナップショットを報告する。dirtyな位置を最大2秒間隔で保存し、選択解除・話／小説切替前とinactive/hidden/paused/detachedの通知でもflushする。連続操作で保存が無期限に延期されるdebounceのみの方式は使わない。

書き込みは単一の順序付きキューで処理し、旧話のflush、新話の選択記録、新話の位置保存の順を保証する。古いレイアウト通知は世代で棄却する。小説削除時には未実行保存を破棄し、実行中の書き込み完了後に削除して履歴の復活を防ぐ。移動時も既存のDB解放順序と協調する。失敗は既存契約どおりWARNINGを出し、その保存を破棄して次の操作を妨げない。

### 4. 復元は一度だけ、明示操作より低い優先度にする

起動時はカタログとライブラリ解決後に最新一件を参照し、登録フォルダの現在の位置をネスト対応で解決する。絶対パスは保存しない。対象不在ならルートを維持し、古い別作品へ自動フォールバックしない。フォルダ入場時は既存の自動選択の条件を維持して本文位置を引き渡す。通常の一覧選択でも保存対象と同じ話なら位置を復元する。

復元要求は対象ファイル・選択世代・オフセットを持ち、コンテンツとレイアウト確定後に一度だけ消費する。待機中に選択・検索・しおり・話移動・手動スクロール／ページ送りが発生したら古い要求を棄却する。既存の`FileEntryStartIntent`の値と意味は維持し、その指定がある場合は保存位置を適用しない。TTS追従中に復元を再発火させない。

復元待ちの一時的な先頭表示を保存しない。表示設定変更では変更前の論理位置を保持し、新レイアウトでその位置を含むページ／行を表示する。再レイアウトだけで保持位置をページ先頭へ繰り返し丸め直さず、実際の読書移動が起きるまで元のアンカーを維持する。

### 5. 本文変更時は先頭へ戻す

本文ハッシュが一致すれば保存位置を使用する。不一致または旧履歴のハッシュ未設定なら話の先頭へ戻し、表示後に新ハッシュを保存する。ハッシュ一致でも範囲外の位置は有効な本文範囲へ補正する。空本文は位置0。ファイルがない場合は既存の未選択一覧を維持する。改稿時の近似検索は意図しない箇所への移動を避けるため初期版では行わない。

## Risks / Trade-offs

- [横書きの計測誤差] → 実レンダリングと同一の計測条件を使い、長い折り返し行・ルビ・末尾で位置が可視かをWidgetテストで検証する。
- [UTF-16とルーンの混同] → 非BMP文字・結合文字・改行・複数文字ルビを含む変換テストを先に作る。
- [急なプロセス終了] → 通常時も最大2秒間隔で保存する。ただしOSによる強制終了直前の未コミット分までの保証はしない。
- [復元と選択保存の競合] → 世代付き要求、保存キュー、復元中の報告抑制を遅延Futureで検証する。
- [改稿時は位置を失う] → 検出可能で決定的な先頭復帰を採用し、文章照合は別変更とする。

## Migration Plan

1. テストファーストで座標変換とDB移行、保存・復元の競合を検証する。
2. v9からv10への加算移行と新規作成のスキーマを一致させ、既存の全移行経路を維持する。
3. 共通コーディネーターと両ビューア、起動・ライフサイクルを接続する。
4. Windows・macOSで再起動と表示変更を確認する。iOS依存処理は追加せず、iOS実機確認は次の変更で行う。
5. ロールバック時にDBを自動ダウングレードしない。旧バイナリへ戻す必要がある場合は更新前バックアップを利用する。

## Open Questions

仕様判断として保留する事項はない。実装時に横書きの描画位置取得方法を小さなWidgetテストで確認し、既存ヘルパーの再利用範囲を確定する。
