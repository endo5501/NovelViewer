## Why

iPad で小説を登録するには、ブラウザで URL をコピーし、アプリに切り替え、ダウンロードボタンを押し、URL を貼り付ける、という 4 ステップを毎回踏む必要がある。アプリの外から URL を直接渡す入口が存在しないため、この往復を短縮できない。

カスタム URL スキームで「ダウンロード要求」を受け取る共通の入口を作れば、iPad ではショートカット経由で共有シートから、デスクトップではブックマークレットから同じ入口を叩ける。さらにこの入口は、後続の iOS Share Extension（共有シートに NovelViewer を直接表示する Phase 2）がそのまま利用する土台にもなる。

## What Changes

- `novelviewer://download?url=<percent-encoded>` 形式のカスタム URL スキームを新設し、アプリが外部からダウンロード要求を受け取れるようにする。
- iOS と macOS の `Info.plist` にスキームを登録する。**Windows と Linux は本変更の対象外**（Windows はスキーム起動が別プロセスを立ち上げるため、単一インスタンス化を先に片付ける必要がある）。
- リンク受信を抽象化した入力源を導入し、コールドスタート時の初回リンクと起動中のリンクの両方を、二重処理せずに単一の保留リクエストへ集約する。
- `DownloadDialog` が保留リクエストを監視し、次のとおり振る舞う。
  - ダイアログ未表示 → URL が入力済みの状態でダイアログを開く
  - ダイアログ表示中かつ入力待ち（idle） → URL 欄を受信した URL に差し替える
  - ダイアログ表示中でそれ以外（ダウンロード中 / 完了 / エラー） → 受け付けず、ダイアログ内に拒否メッセージを表示する
- スキーム受信による**無言ダウンロードは行わない**。悪意のあるページからスキームを叩かれても、必ずダイアログでユーザーの確認を経てからダウンロードを開始する。
- 受信 URL は既存の `NovelSiteRegistry` の検証（http/https 以外を拒否）をそのまま通す。対応サイト以外は従来どおり `GenericWebSite` のフォールバックで Web 記事として扱う。
- 拒否メッセージの文言を en / ja / zh の 3 言語に追加する。
- iPad でショートカットを使って共有シートから呼び出す手順を README に記載する。

## Capabilities

### New Capabilities
- `download-request-url-scheme`: カスタム URL スキームによる外部からのダウンロード要求の受理。スキームの登録、リンクの受信と正規化、保留リクエストの単一化、ダウンロードダイアログへの反映と拒否、確認なしダウンロードの禁止を扱う。

### Modified Capabilities
（なし。既存 spec の要件は変更しない。`text-download` のダウンロード挙動そのものは変わらず、本変更は起動経路を追加するのみ。）

## Impact

- **依存追加**: `app_links`（全プラットフォーム対応。デスクトップのビルドには影響しない）
- **ネイティブ設定**: `ios/Runner/Info.plist`、`macos/Runner/Info.plist` に `CFBundleURLTypes` を追加
- **Dart**: `lib/features/text_download/` 配下にリンク受信の抽象と保留リクエストのプロバイダを追加。`DownloadDialog` に初期 URL の受け入れと拒否表示を追加。`HomeScreen` に保留リクエストの監視を追加
- **l10n**: `lib/l10n/app_en.arb` / `app_ja.arb` / `app_zh.arb` に文言を追加
- **文書**: README に iPad のショートカット設定手順と、スキーム登録の手動確認手順を追加
- **テスト**: Dart 側は fake のリンク入力源で自動テスト可能。スキーム登録が OS 側で効いているかは実機での手動確認となる
- **Phase 2 への接続**: iOS Share Extension は本変更で作る入口を叩くだけなので、Dart 側に追加変更なく載せられる
