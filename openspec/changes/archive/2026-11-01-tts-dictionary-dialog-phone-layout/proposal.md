# Proposal

## Why

iPhoneで読み上げ辞書ダイアログを開くと、追加フォームの「表記」「読み」の入力欄が幅約30ptまで潰れ、ラベルも入力内容も読めない。フォームは入力欄2つ・「読み上げしない」チェックボックスとラベル・追加ボタンを1つの `Row` に並べている。iPhone縦向きのダイアログ内容幅（約265pt）では、幅の固定な部品だけで約204ptを取り、入力欄にはほとんど残らない。iPhone対応（`ios-iphone-support`）の動作確認で見つかった。

## What Changes

- 辞書ダイアログの追加フォームが、自分に与えられた幅を見てレイアウトを切り替える。
  - 広い幅（macOS / Windows / iPad。ダイアログ内容幅 480）: 今の1行レイアウトのまま。
  - 狭い幅（iPhone縦向き）: 「表記」と「読み」をそれぞれ全幅の1行に置き、その下の行に「読み上げしない」チェックボックスと追加ボタンを置く。
- 狭い幅ではフォームが高くなるため、ソフトウェアキーボードが出てダイアログの高さが縮んでもオーバーフローしないようにする。内容全体がスクロールし、入力中の欄が見える状態を保つ。
- ウィンドウのリサイズや端末の回転でブレークポイントをまたいでも、入力途中の欄の内容・フォーカス・IME変換が失われない（TTS編集画面のセグメント行と同じ方式）。
- 範囲外: 辞書ダイアログがTTS編集ダイアログの上に重なって見える件。辞書の追加・削除・変換の挙動の変更。

## Capabilities

### New Capabilities

（なし）

### Modified Capabilities

- `tts-dictionary`: 辞書ダイアログの追加フォームが利用可能幅に応じてレイアウトを切り替え、狭い幅とキーボード表示中でも入力欄が読める、という要件を追加する。

## Impact

- `lib/features/tts/presentation/tts_dictionary_dialog.dart`: `_buildAddRow()` と `build()` のレイアウト。
- `test/features/tts/presentation/tts_dictionary_dialog_test.dart`: 狭い幅、広い幅、キーボード表示中のウィジェットテストを追加。
- データベース、リポジトリ、辞書変換、l10n 文字列には変更なし。新しい依存パッケージもない。
