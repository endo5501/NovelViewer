## 1. 何を決めたいのか

現在 NovelViewer は Irodori v4 に caption を渡していない（`TtsEngineConfig.captionFromMemo` で無条件に遮断）。
理由は「参照音声 × caption」で末尾に本文にない発話が付くため。本アプリの主経路がそれに当たる。

`FINDINGS.md` で原因は特定済み: **duration predictor が尺を与えすぎ、余った時間をモデルが喋って埋める。**

| mode | 予測尺 | 本文終端 | 余り | 余分な区間 |
|---|---:|---:|---:|---:|
| noref | 5.56 | 5.49 | 0.07 | 0/10 |
| caption のみ | 6.96 | 6.62 | 0.34 | 0/10 |
| 参照のみ | 7.44 | 6.15 | 1.29 | 1/10 |
| **参照+caption** | **7.96** | **5.34** | **2.61** | **9/10** |

尺だけを外から縮めると消えることも確認済み（7.96→9/10、7.44→2/10、6.20→0/10）。

**この計画で決めたいのは、この補正を製品に入れてよいか、入れるならどの値か。**

## 2. 仮説

### H1（中心仮説）

> 参照音声 + caption を与えても、RF 本体はテキストを **noref 相当の速さ**で読み終える。
> したがって **noref 条件での duration 予測値 P** に小さなマージン α を足した尺を与えれば、
> 余りが詰まり末尾アーティファクトが消える。

根拠（n=1、`FINDINGS.md`）:

- noref の**予測** 5.56s ≒ 参照+caption での**実際の**本文終端 5.34s（C++ 側 5.37s）
- noref 条件でだけ predictor は正確（余り 0.07s）
- 唯一 0/10 を出した `--seconds 6.20` は 5.56 + 0.64 に相当する

### H2（安全性）

> 尺を P + α に縮めても本文は切れない。モデルは発話速度を落として尺に合わせる。

`FINDINGS.md` の固定尺検証で観測済みだが、**caption が明示的に「ゆっくり話す」を要求する場合**は
噛み合わない可能性がある。これが H2 の主たる反証条件。

### 検証されないもの（あえて問わない）

前段の検討では「過剰見積もりは加算オフセットか倍率か」が未知だった。
実測は加算合成（+1.40 / +1.88 → +3.28 予想 vs 実測 +2.40）でも
乗算合成（×1.252 / ×1.338 → ×1.675 予想 vs 実測 ×1.432）でも説明できず、
gated fusion なので当然ではある。

**採用する実装方針（後述 D-2）は predictor 自身に noref 条件で答えさせるため、この問いは回避される。**
`duration_scale` に固定倍率を入れる案（B 案）を採るなら必要な検証だが、B 案は採らない。

## 3. 実装方針の前提（何を検証すれば実装が正当化されるか）

採用予定は **D-2: audio.cpp fork の engine 内で完結させる**。

```
                    現状                            D-2
  ┌───────────────────────────┐      ┌───────────────────────────┐
  │ condition run             │      │ condition run             │
  │  has_speaker=1            │      │  has_speaker=1            │
  │  has_caption=1            │      │  has_caption=1            │
  │  → pred 7.96s ────────┐   │      │  → pred 7.96s             │
  └───────────────────────│───┘      ├───────────────────────────┤
                          │          │ condition run (2回目)      │← 追加
                          │          │  has_speaker=0            │
                          │          │  has_caption=0            │
                          │          │  → pred P=5.56s ─┐        │
                          │          └──────────────────│────────┘
                          ▼                             ▼ + α
              latent_steps = 7.96s          latent_steps = min(7.96, P+α)
```

技術的成立根拠（調査済み）:

| 事実 | 場所 |
|---|---|
| `has_speaker` / `has_caption` は**実行時入力テンソル**。run のたびに書き換えている | `condition_encoder.cpp:1316-1318, 1417-1422` |
| `use_caption_condition` はモデルが caption 重みを持つかのアセット側フラグ。リクエスト単位ではない | `condition_encoder.cpp:860, 887` |
| 尺の決定は 25 行の局所領域 | `session.cpp:584-609` |
| 同関数にはすでに自前パッチの前例がある | `session.cpp:546 "NovelViewer abort patch"` |
| engine 側に `duration_sec` / `duration_scale` / `min/max_duration_sec` は実装済み。C シムが渡していないだけ | `types.h:10-30` / `audiocpp_c_api.cpp:385-417` |

**Dart 側から予測 API を呼ぶ案（D-1）を採らない理由:**
audio.cpp は渡されたテキストを内部で分割する（`session.cpp:441-448` `chunk_text_request`、既定 Endline / max_text_len）。
予測も尺決定もチャンクごとのループ内（`session.cpp:564, 586`）。
Dart は分割境界を知らないため、`chunk_text_request` を再実装しない限りチャンクと予測値を対応づけられない。
また現行の `duration_sec` は 586 行がループ内にあるため、**指定秒数が全チャンクに同じ値で適用**され、
複数チャンクのテキストでは使い物にならない。

**この計画で検証するのは D-2 が実装する規則そのもの。** Python 経路で `--seconds (P + α)` を明示指定すれば、
C++ を 1 行も書かずに同じ計算結果を再現できる。

## 4. 事前作業（ハーネスの修正が 1 点必要）

`python/analyze_tail.py:92` で `text_end` が **3 番目の区間の終端に固定**されている。

```python
text_end = (segs[2][1] if len(segs) >= 3 else segs[-1][1]) * hop
```

現行のテスト文が 3 区間に分かれることに依存した実装。本計画は**複数のテキスト**を扱うため、
このままでは `text_end` / `surplus` が他のテキストで誤った値になる。

- [x] **T0.** 対応済み（2026-08-12）。実際に入れた変更は 3 点:
  1. `text_end` の基準区間数 k を、`--text-segments N` の明示指定、無ければ**基準 mode の最頻区間数**から決定。
     区間分割は `analyze()` に残し、k の適用は `set_text_end()` に分離した。
     アーティファクト判定 (`n_seg > k`) も同じ k を使うよう統一。
  2. `mode_of()` が `--tag` を mode 名に含めるようにした (`v4py-clone_caption-seed1234-a070` → `clone_caption@a070`)。
     `rglob` は再帰するので、**基準ディレクトリと α ごとのディレクトリを親ディレクトリ 1 回の解析でまとめて出せる。**
  3. 区間数が k を**下回った**本数を「※要試聴」として表示。区間併合（切断ではない）だが、
     その clip ではアーティファクト指標が効かないため。
  - **回帰確認済み**: `out/python-sweep` を再解析し、修正前と `tail_analysis_python.csv` が**バイト単位で一致**。
    表も `python/FINDINGS.md` §3 と同一（k は自動で 3 と判定された）。

その他の注意:

- 出力ファイル名は `v4py-{mode}-seed{seed}[-{tag}].wav`。`mode_of()` の正規表現は `^v4py-([a-z_]+)-seed` なので
  `--tag` は mode 解析を壊さない。
- ただし **テキストが違うものを同一ディレクトリに混ぜない。** 判定が「基準 mode の最頻区間数」との比較のため、
  テキストごとに区間数が変わると全滅する。**1 テキスト = 1 出力ディレクトリ**。

## 5. 実験計画

### 5.1 変数

| 変数 | 水準 | ねらい |
|---|---|---|
| テキスト | T1 既存文（3 区間, 5.6s 相当）/ T2 短文（1 文, ~2s）/ T3 中文（~10s）/ T4 長文（複数文, ~20s） | 規則がテキスト長に追従するか。短文・長文が最大のリスク |
| caption | C1 既存（悲痛・弱々しい）/ C2 **明示的に遅い**（「ゆっくりと、間を取って穏やかに」）/ C3 速い・元気 | H2 の反証条件。C2 が本命の危険ケース |
| 参照音声 | R1 `ref/ref.wav`（7.0s）/ R2 別話者（用意できれば） | speaker embedding 依存の確認 |
| α（マージン） | 0.4 / 0.7 / 1.0 秒 | 決めたい値 |

### 実際に使用した水準（2026-08-12 確定）

```
T1 (既存, 3区間, P=5.560s)
  どうしてもっと早く教えてくれなかったの？私、ずっと待ってたのに。
T2 (短文)  ※ 2026-08-07 の 2x2 と同一文にして比較可能にする
  こんにちは、テストです。
T3 (中文)
  窓の外では、粉雪が音もなく降り積もっていた。彼女はカーテンの隙間から
  その白い景色を、ただ黙って見つめている。
T4 (長文)
  T3 + 昨日までの喧騒が嘘のように、街は静まり返っていた。もう誰も、
  あの日のことを口にしようとはしない。

C1 (既存) 深く傷つき、今にも泣き出しそうな様子。声が震えており、悲痛なトーンで弱々しく話す。
C2 (遅い) ゆっくりと間を取りながら、落ち着いた低い声で穏やかに語りかける。
C3 (速い) 明るく元気いっぱいに、弾むような早口で楽しそうに話す。

R1 ref/ref.wav     6.99s / 44.1kHz / stereo
R2 ref/ref113.wav  1.13s / 44.1kHz / stereo
```

- **T1 の基準セルは既存の `out/python-sweep` を再利用する。** テキスト・caption・参照・steps・seed
  (1234-1243) がすべて一致するため、`clone` / `clone_caption` 各 10 本をそのまま基準に使える。
  P も同スイープの `noref` から確定済み（`frames=138.8 ... (5.560s)`、seed 非依存）。
  → 基準セルで新規に回すのは α の 30 本のみ。
- **R2 は 1.13 秒しかない。** 参照音声としては短すぎる部類で、話者依存性の検証としては
  「別話者」と「極端に短い参照」の交絡が残る。結果の解釈時に留意する。

全交差はやらない。**基準セル T1×C1×R1 で α を決め、他の水準は 1 変数ずつ振って規則の頑健性を見る。**

### T2（短文）の扱い — 別の発生条件と重なる

2026-08-07 の追加検証（v4 f16 / Vulkan / caption なし / 各セル 1 seed）で、
**「参照音声なし × 短文」も末尾アーティファクトの発生条件**であることが確認されている。
caption のときと同様、単独要因ではなく交互作用。

| 参照音声 | テキスト | 結果 |
|---|---|---|
| なし | **短文** | **発生** |
| あり | 短文 | クリーン |
| なし | 長文 | クリーン |
| あり | 長文 | クリーン |

T2 セルへの影響:

- **① の noref プローブは影響を受けない。** 読むのは predictor の出力値 P だけで、生成音声は判定に使わないため。
- **② の clone 基準は上表では「参照あり × 短文 = クリーン」**なので基準としては使える見込み。
  ただし各セル 1 seed の弱い確度なので、**基準側に余分な区間が出たら T2 は判定不能として切り離す**。
- 短文は区間数が 1〜2 に落ちるため、「区間数の増加」という指標そのものが脆くなる。T2 は全数試聴する。

**むしろ好機でもある。** この条件も余りが原因なら、noref×短文の余りは大きいはずで、
同じ補正で両方が救えることになる。T2 の noref プローブで
「P（noref 予測）と実際の本文終端の差」を記録しておくと、2 条件が同一機構かどうかが分かる。

### 5.2 手順（1 セルあたり）

```
① noref で 1 seed だけ回す          → P（予測尺）を取得
     ※ predicted duration は seed 非依存の決定論的な値。10 本回す必要はない
② clone（参照のみ）10 seed          → 基準 mode。区間数の基準値と対照データ
③ clone_caption 補正なし 10 seed    → このセルでの素の発生率
④ clone_caption --seconds (P+α) 10 seed × α 3 水準
⑤ analyze_tail.py で ②③④ を集計
```

1 セル = 1 + 10 + 10 + 30 = **51 本**。

> **P はテキストにのみ依存する**（caption / 参照音声を外した条件での予測値なので）。
> したがって ① のプローブは**テキストごとに 1 回**でよく、C2 / C3 / R2 のセルは T1 の P を再利用できる。
> 上の 51 本は基準セルの数字で、追加セルは 50 本ずつ。

## 6. 判定基準

α を製品に採用してよいと判断する条件:

1. **主基準:** 全セルで余分な区間 **0 本**。
   - 数百チャンクの朗読が用途なので「9/10 → 2/10」は不合格。上流 Issue ドラフトが勧める
     `duration_scale 0.93`（参照のみの予測値に合わせる案）はこの基準で落ちる。
2. **本文が切れていない。** `n_seg` が基準 mode を**下回らない**こと。
   区間の併合（間が詰まって 3→2 区間）は切断ではないので、下回った場合は必ず試聴で判別する。
3. **不自然な間延び・早口がない。** 区間数だけでは検出できないため、各セル最低 2 本は試聴する。
   特に C2（遅い caption）は全数聴く。
4. **安全弁が妥当に働く。** `P + α > 通常予測` となるケースがあれば記録する（その場合 D-2 は通常予測を使う）。

例外: **T2（短文）と T4（長文）は主基準から外す。** それぞれ別の発生条件・上流既知の劣化と
交絡するため（§7）。両者は「補正が悪化させていないこと」の確認にとどめ、
α の採否は T1 / T3 と caption・参照の各水準で決める。

### 「0 本」の意味について

10 seed で 0/10 は「発生率 10% 未満」程度しか言えない。数百チャンク運用では不足。
本計画は**セルを横断して合計 40〜60 本規模で 0** を確認する設計であり、それでも
「1% 未満」程度が上限。したがって:

- **末尾トリム（生成後に音響的に切る）を第 2 防衛線として残す**かどうかを、この結果を見て判断する。
- 予防（尺補正）と対症（トリム）の二段構えにするなら、トリムは保守的な閾値でよい。

## 7. 限界とリスク

| 項目 | 内容 |
|---|---|
| steps | 本計画は 24（CPU 都合）。本番既定は 40。**採用 α で 1 セルだけ steps=40 の確認を行う。** |
| 経路差 | 検証は PyTorch 本家。製品は GGUF q8_0 + audio.cpp。`FINDINGS.md` で両者の予測尺・余り・発生率がほぼ一致することは確認済みだが、**採用後に C++ 側で再確認が要る**（下記 §8 フェーズ 3）。 |
| チャンク分割 | Python ハーネスは単一テキストを分割しない。**分割まわりの正しさは C++ 側でしか検証できない。** |
| RNG | C++ と PyTorch で乱数生成器が違うため seed 単位の一致は原理的に取れない。比較できるのは発生率のみ。 |
| 参照音声 | 手元にあるのは 1 本。R2 が用意できなければ speaker 依存性は未検証のまま残る。 |
| 文字起こし | 判定は音響プロキシ（区間数 + 末尾無音）。余分な区間が意味のある発話かは試聴で確認する。 |
| **T2 の交絡** | 「参照音声なし × 短文」という**別の発生条件**と重なる（§5.1）。補正後も T2 でアーティファクトが出た場合、H1 の反証とは限らない。基準 mode 側にも出ていれば判定不能として切り離す。 |
| **T4 の交絡** | 上流 Issue [#13](https://github.com/Aratako/Irodori-TTS/issues/13) — 学習データが 30 秒以下でその近辺も少ないため、**長い生成は余りと無関係に劣化する**（作者回答: 句読点でチャンク分割してほしい）。補正ありで T4 が壊れた場合、#13 の可能性を先に疑う。また**本番経路では長文は audio.cpp が自動分割する**ため、T4 の失敗は情報にはなるが不合格の根拠にはならない。 |

**この検証が不合格だった場合**は、D-2 を諦めて (a) 末尾トリム単独、(b) 現状維持 + 上流 Issue 提出、
のどちらかに落とす。`issues/irodori-tts-tail-issue-draft.md` は提出可能な状態にある。

### 候補ルール #2 — 文字数比例（D-2 の代案）

短文で neural predictor が崩れる一方、**単純な文字数比例の方が実発話長をよく当てる**ことが分かった。

| | token 数 | 字数(記号除) | noref 実測本文終端 | 秒/token | **秒/字** |
|---|---:|---:|---:|---:|---:|
| T1 | 13 | 29 | 5.49 | 0.4223 | 0.1893 |
| T2 | 6 | 10 | 2.05 | 0.3417 | 0.2050 |
| T3 | 26 | 50 | 10.35 | 0.3981 | 0.2070 |
| ばらつき | | | | ±11% | **±5%** |

**トークンより文字の方が安定。** これは実装形態を変えうる:

```
候補#1 (D-2):  latent_steps = min(predictor_out, noref_predictor_out + margin)
               → condition graph の 2 回目実行が必要
               → 短文で noref 予測自体が +83% ずれるため T2 を救えない可能性

候補#2:        latent_steps = min(predictor_out, chars × rate + margin)
               → 2 回目の実行が不要。session.cpp の判断点に生テキストがある
               → 短文でも当たる
               → 日本語の符号点数に依存するので他言語では要再校正
```

**ただし単一の rate では張力がある**（rate を大きく取ると T1 で余りが増え、小さく取ると T3 が切れる）:

| rate, margin | T1 (実長5.49) | T2 (実長2.05) | T3 (実長10.35) |
|---|---:|---:|---:|
| 0.190, 0.4 | 5.91 → 余り 0.4 ✅ | 2.30 → 余り 0.25 | **9.90 → 実長より短い ❌ 切断懸念** |
| 0.207, 0.4 | 6.40 → 余り 0.9 △ | 2.47 | 10.75 → 余り 0.4 ✅ |

**実行済みの `out/dur-T3/p1075` (10.75) と `out/dur-T2/p245` (2.45) は、
偶然この rate=0.207 / margin=0.4 の値とほぼ一致する。** 試聴でこの候補が同時に検証される。

**確定にはテキストをもっと増やして rate を当てる必要がある。** 現時点では n=3。

```

   R1(6.99s) × C1  → 7.96    R1 を 2.0s に切る × C1 → 8.04
   R1(6.99s) × C2  → 8.56    R2(1.13s, 別話者) × C1 → 6.24
   R1(6.99s) × C3  → 7.28
別テキスト T3 (noref 予測 11.20)
   R1 × C1         → 11.64   ← ほぼ過剰見積もりが無い
```

固定倍率（B 案）も固定オフセットも成立しないことが改めて確認された。

**4. 区間数プロキシが条件によって機能しない。**
T3 は noref 基準ですら 2/10、clone で 3/10 が「発生」と判定される（本文が 4〜6 区間に
seed 依存で割れるため）。C2 は「間を取りながら」という caption なので本文自身の区間が増える。
検出箇所の間隔も、補正なし T1 の 1.0〜1.7s に対し補正後は 0.22〜0.82s と自然な区切りの範囲。
**→ 試聴による決着が必要（`listening/1-python-alpha-sweep.md`）。**

### 試聴結果 3 (2026-08-12、ユーザ判定、`listening/3-python-final-rule.md`)

| # | 条件 | 尺 | 余り | 試聴 |
|---|---|---:|---:|---|
| I1 | T1 × C2 遅い caption | 5.56 | 0.06 | **末尾音声なし・欠けなし** |
| I2 | T1 × C2 遅い caption (別 seed) | 5.56 | 0.06 | **末尾音声なし・欠けなし** |
| I3 | R2 別話者（プロキシが 1/10 フラグ） | 5.56 | 0.42 | **末尾音声なし・欠けなし。**ただし物音のような音が本文**直後**に入る |
| I4 | T1 × C1 標準 | 5.56 | 0.44 | **末尾音声なし・欠けなし** |
| I5 | T1 × C1 **steps=40** | 5.56 | 0.44 | **末尾音声なし・欠けなし** |

**steps=24 で得た結論は本番既定の steps=40 に外挿できる。**（本文終端・余りも steps=24 と完全一致）

**I3 の所見（ユーザ）:** 「本文の直後に入っているため少し性質が違う。従来の現象は本文読み上げ後、
少し間を置いてから発音があった。この程度なら無視するか再生成で解消される」

→ プロキシが検出した区間長 0.16 秒・直前ギャップ 0.23 秒という数値と整合する。
**本現象（間を置いてから別の発話が入る）とは別物**として扱う。

**遅い caption を余り 0.06 秒まで詰めても欠けも早口も出なかった** ため、
G2/G3 で見えた下端の劣化は 5.36 秒（noref 予測を 0.2 秒下回る）で初めて現れる。
**noref 予測を下回らない限り安全**、という理解と整合する。

## 10. 結論

### 採用ルール

```
target_seconds = min( 通常の duration 予測 ,
                      noref 条件での duration 予測 ,
                      字数(記号除) × 0.207 + 0.4 )
```

`min_duration_sec` / `max_duration_sec` の既存クランプはそのまま適用する。

### 判定: **合格。OpenSpec change の起票に進める。**

試聴で確認した全 9 条件で、末尾の余計な発話も本文の欠けも出なかった。

| 条件 | ルールが出す尺 | 効いた項 | 試聴 |
|---|---:|---|---|
| T1 × C1 標準 | 5.56 | noref 予測 | ✅ I4 |
| T1 × C2 遅い caption | 5.56 | noref 予測 | ✅ I1 / I2 |
| T1 × C3 速い caption | 5.56 | noref 予測 | ✅ G1 |

| T3 長文 | 10.75 | **字数則** | ✅ H1 |

補正なしでは同じ条件が 8〜9/10 で壊れていた（A1 / B1 / C1 / E2 で試聴確認済み）。

### 末尾トリムを第 2 防衛線に入れるか: **入れない**

- 予防（尺補正）だけで全条件がクリーンになった
- 「本文直後の物音」（I3）はトリムでは取れない位置にあり、かつ実害が無いと判断された
- **正当な間と区別できないリスク**を負う理由が無くなった
- 必要になったら後から足せる。初手では入れない
