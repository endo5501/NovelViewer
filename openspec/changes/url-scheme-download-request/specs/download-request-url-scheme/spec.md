## ADDED Requirements

### Requirement: カスタム URL スキームの登録

システムは、アプリ外部からダウンロード要求を受け取るためのカスタム URL スキーム `novelviewer` を、iOS と macOS のアプリバンドルに登録しなければならない (MUST)。登録は各プラットフォームの `Info.plist` の `CFBundleURLTypes` で行うものとする (SHALL)。

Windows および Linux にはスキームを登録してはならない (MUST NOT)。Windows はスキーム起動が既存プロセスとは別のプロセスを立ち上げるため、同一の SQLite ファイルを複数プロセスが掴む問題を先に解決する必要があり、本仕様の対象外とする。

#### Scenario: iOS でスキームが登録されている
- **WHEN** iOS 向けにビルドされたアプリバンドルの `Info.plist` を検査する
- **THEN** `CFBundleURLTypes` に `novelviewer` スキームが含まれる

#### Scenario: macOS でスキームが登録されている
- **WHEN** macOS 向けにビルドされたアプリバンドルの `Info.plist` を検査する
- **THEN** `CFBundleURLTypes` に `novelviewer` スキームが含まれる

#### Scenario: Windows にはスキームを登録しない
- **WHEN** Windows 向けのインストーラ定義およびアプリ起動処理を検査する
- **THEN** `novelviewer` スキームのハンドラ登録は行われていない

### Requirement: ダウンロード要求 URL の形式と解釈

システムは、`novelviewer://download?url=<percent-encoded>` の形式で受け取ったリンクを、ダウンロード対象 URL を含むダウンロード要求として解釈しなければならない (MUST)。`url` クエリパラメータの値はパーセントデコードして対象 URL を得るものとする (SHALL)。

ホストが `download` 以外のリンク、`url` クエリパラメータを持たないリンク、および `url` の値が空のリンクは、ダウンロード要求として解釈してはならない (MUST NOT)。これらは無視するものとする (SHALL)。

#### Scenario: 正しい形式のリンクが要求として解釈される
- **WHEN** `novelviewer://download?url=https%3A%2F%2Fncode.syosetu.com%2Fn1234ab%2F` を受信する
- **THEN** ダウンロード対象 URL `https://ncode.syosetu.com/n1234ab/` を持つダウンロード要求が生成される

#### Scenario: ホストが download 以外のリンクは無視される
- **WHEN** `novelviewer://other?url=https%3A%2F%2Fexample.com%2F` を受信する
- **THEN** ダウンロード要求は生成されない
- **AND** ダウンロードダイアログは開かれない

#### Scenario: url パラメータを持たないリンクは無視される
- **WHEN** `novelviewer://download` を受信する
- **THEN** ダウンロード要求は生成されない
- **AND** ダウンロードダイアログは開かれない

### Requirement: 受信 URL のスキーム検証

システムは、ダウンロード要求から取り出した対象 URL が http または https 以外のスキームである場合、その要求を受け付けてはならない (MUST NOT)。検証は既存のサイト解決（`NovelSiteRegistry`）が行う http/https 判定と同一の判断に従うものとする (SHALL)。

#### Scenario: http 以外のスキームは受け付けない
- **WHEN** `novelviewer://download?url=file%3A%2F%2F%2Fetc%2Fpasswd` を受信する
- **THEN** ダウンロード要求は生成されない
- **AND** ダウンロードダイアログは開かれない

#### Scenario: パースできない文字列は受け付けない
- **WHEN** `url` パラメータの値が URL としてパースできない文字列である
- **THEN** ダウンロード要求は生成されない
- **AND** ダウンロードダイアログは開かれない

### Requirement: 確認を経ないダウンロードの禁止

システムは、URL スキームの受信のみを契機としてダウンロードを開始してはならない (MUST NOT)。受信した対象 URL は必ずダウンロードダイアログに提示し、ユーザーが開始操作を行って初めてダウンロードを開始するものとする (SHALL)。これは、任意の Web ページがスキームを叩くだけでダウンロードを誘発できる状態を避けるためである。

#### Scenario: 受信だけではダウンロードが始まらない
- **WHEN** 有効なダウンロード要求を受信する
- **THEN** ダウンロードは開始されない
- **AND** 対象 URL が入力された状態のダウンロードダイアログが表示される

#### Scenario: ユーザーの開始操作でダウンロードが始まる
- **WHEN** 受信によって開かれたダウンロードダイアログで、ユーザーが開始操作を行う
- **THEN** 対象 URL に対するダウンロードが開始される

### Requirement: 起動時リンクと起動中リンクの単一化

システムは、アプリ未起動時のリンクによる起動（コールドスタート）で渡された初回リンクと、起動中に受信したリンクの双方を、同一のダウンロード要求経路で処理しなければならない (MUST)。初回リンクを二重に処理してはならない (MUST NOT)。

#### Scenario: コールドスタートの初回リンクが一度だけ処理される
- **WHEN** アプリ未起動の状態でリンクによりアプリが起動される
- **THEN** ダウンロードダイアログが対象 URL 入りで一度だけ表示される
- **AND** 同一の要求が再度処理されることはない

#### Scenario: 起動中の受信が処理される
- **WHEN** アプリが起動している状態でリンクを受信する
- **THEN** 同じ経路でダウンロード要求として処理される

### Requirement: ダウンロードダイアログへの反映と拒否

システムは、ダウンロード要求を受理した時点のダウンロードダイアログの状態に応じて、次のいずれかの振る舞いをしなければならない (MUST)。

- ダイアログが表示されていない場合、対象 URL が入力された状態でダイアログを開くものとする (SHALL)。
- ダイアログが表示されており、ダウンロード状態が入力待ち（`idle`）の場合、URL 入力欄の内容を対象 URL に差し替えるものとする (SHALL)。
- ダイアログが表示されており、ダウンロード状態が入力待ち以外（ダウンロード中・完了・エラー・キャンセル済み）の場合、要求を受け付けず、受け付けなかったことを示すメッセージをダイアログ内に表示するものとする (SHALL)。

拒否の通知をダイアログの外側（スナックバー等）に表示してはならない (MUST NOT)。ダウンロード中のダイアログは閉じられないモーダルであり、外側の通知はユーザーから見えないためである。

#### Scenario: ダイアログ未表示のときは URL 入りで開く
- **WHEN** ダウンロードダイアログが表示されていない状態でダウンロード要求を受理する
- **THEN** ダウンロードダイアログが表示される
- **AND** URL 入力欄に対象 URL が入力されている

#### Scenario: 入力待ちのダイアログでは URL が差し替わる
- **WHEN** ダウンロードダイアログが表示されており、ダウンロード状態が `idle` のときにダウンロード要求を受理する
- **THEN** ダイアログは二重に開かれない
- **AND** URL 入力欄の内容が対象 URL に差し替わる

#### Scenario: ダウンロード中は受け付けず、ダイアログ内に通知する
- **WHEN** ダウンロード状態が `downloading` のときにダウンロード要求を受理する
- **THEN** URL 入力欄の内容は変化しない
- **AND** ダウンロードは開始されない
- **AND** 受け付けなかったことを示すメッセージがダイアログ内に表示される

#### Scenario: 完了表示中も受け付けない
- **WHEN** ダウンロード状態が `completed` のときにダウンロード要求を受理する
- **THEN** ダイアログは二重に開かれない
- **AND** 受け付けなかったことを示すメッセージがダイアログ内に表示される

### Requirement: 対応サイト判定は既存の経路に従う

システムは、URL スキーム経由で受け取った対象 URL について、専用アダプタを持たないサイトであることを理由に拒否してはならない (MUST NOT)。対応サイトの判定と、汎用 Web 記事としての取り込みへのフォールバックは、ユーザーが手入力した場合と同一の経路に従うものとする (SHALL)。

#### Scenario: 専用アダプタを持たない URL も受理される
- **WHEN** 小説サイト以外の http(s) URL を含むダウンロード要求を受信する
- **THEN** ダウンロードダイアログが対象 URL 入りで表示される
- **AND** 汎用 Web 記事としてコレクションに取り込む選択肢が提示される

### Requirement: 拒否メッセージの多言語対応

システムは、ダウンロード要求を受け付けなかったことを示すメッセージを、アプリが対応する全ての表示言語（英語・日本語・中国語）で提供しなければならない (MUST)。

#### Scenario: 各言語で文言が定義されている
- **WHEN** 多言語リソースを検査する
- **THEN** 拒否メッセージのキーが英語・日本語・中国語のすべてに存在する
