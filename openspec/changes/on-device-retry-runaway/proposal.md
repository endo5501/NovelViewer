# Proposal

## Why

iPhone（iOS 27.0.1）で Apple オンデバイスモデルによる用語要約を実行すると、要約が「〈記憶人〉は…人口が少ない。」} 支援者: Appleです。 支援者: Appleです。 …」のような壊れたテキストになり、そのまま保存・表示された。iPhone の DB には、同じ形で壊れた要約が「記憶人シィー」と「キャロル」の2件残っていた。

実機での計測（`measurements/iphone16-ios27.0.1-before.json`）で、原因はスキーマ制約付きの生成にあるとわかった。モデルは要約を書き終えると、文字列を `"` ではなく全角の `」` で閉じたつもりになって `」}` と書く。このとき文字列は閉じていないので、そのまま文字列の中で応答上限まで書き続ける。最後はフレームワークが JSON を閉じて返す。制約付きの生成は5回とも約20秒かけて上限まで走り、guardrail の拒否は1回もなかった。返ってくる JSON は正しく読めるので、パイプラインは成功した回答として保存し、警告も残らない。同じプロンプトでも、スキーマなしなら iPhone でも約1秒で正しく答え、macOS 27.0.1 と iPadOS 26.6.2 では制約付きでも問題は出ていない。端末ごとのモデルの違いであり、OS 更新で直るのを待つ問題ではない。

## What Changes

- **暴走を元から断てるかを、先に実機で試す。** 制約付きのプロンプトから JSON の例示の行を外す、フィールドの値に `}` を禁じる正規表現の制約を付ける、スキーマをプロンプトに含めない、の3つを試す。効いたものは採用し、仕様と設計に反映する。
- **制約付きの回答が暴走したら、プロバイダが打ち切ってスキーマなしの要求に切り替える。** 制約付きの回答も逐次受け取る。フィールドの値が宣言した応答予算を超えたとき、または値に `}` が現れたときは暴走とみなして打ち切る（`}` は、モデルが自分では閉じたつもりでいることを示す）。そのうえで、guardrail に拒否されたときと同じスキーマなしの要求を1回だけ出す。事実抽出と最終要約の両方に効く。
- **スキーマなしの回答も、プロバイダが打ち切る。** 最上位の JSON オブジェクトが閉じたらそこで止め、オブジェクトだけを返す（コードフェンスは返さない）。オブジェクトが閉じないまま値が応答予算を超えたら、打ち切って「回答が暴走した」という独立した失敗として報告する。この失敗は再試行に値するものとして扱う。
- **BREAKING（全プロバイダ）: 読めない最終要約を要約として保存しない。** 最終要約が2回とも JSON として読めなかった場合や、2回目の要求自体が失敗した場合は、生テキストを要約として保存・表示しない。要約を読み取れなかった理由を示して解析を失敗させる。Ollama・OpenAI 互換のプロバイダが地の文で答えた場合もこれに含まれる。Stage 1 の生テキストへのフォールバックは残す。今回の不具合はパースに成功してしまうので、この変更だけでは防げない。壊れた回答を表示しないための防御として入れる。
- **実機の計測テストで、修正前と修正後を確かめる。** 回答の先頭だけでなく末尾も記録する。
- greedy サンプリングと、拒否されたときの再試行（1回だけ、スキーマなしで）は変えない。

## Capabilities

### New Capabilities

（なし）

### Modified Capabilities

- `apple-on-device-llm`: 制約付きの回答が暴走したときの打ち切りと、スキーマなしの要求への切り替え。スキーマなしの回答の打ち切り（オブジェクトが閉じた時点、応答予算の超過）と、それが返す形。新しい失敗の原因「暴走」と、その再試行の扱い。応答上限と応答予算の関係。実験で採用したものがあれば、プロンプトやスキーマの作り方
- `llm-summary-pipeline`: 最終要約の生テキストへのフォールバックを撤廃し、読めない最終要約は失敗として扱う。生テキストへのフォールバックは Stage 1 に限定する

## Impact

- ネイティブ: `packages/foundation_models_llm/darwin/foundation_models_llm/Sources/foundation_models_llm/FoundationModelsLlmPlugin.swift`（逐次受信、打ち切り、実験用の引数）。打ち切りの判定は Flutter ビルドの外でテストできるよう、`packages/foundation_models_llm/darwin/wire_code_tests` と同じ方式の独立した Swift パッケージに置く
- Dart プラグイン: `packages/foundation_models_llm/lib/src/`（メソッドチャネルの引数、`OnDeviceGenerationFailure` への新しい原因の追加）
- クライアント: `lib/features/llm_summary/data/foundation_models_client.dart`（暴走したときの切り替え、応答予算の受け渡し）、`lib/features/llm_summary/domain/llm_analysis_failure.dart`
- パイプライン: `lib/features/llm_summary/data/llm_summary_pipeline.dart`（最終要約の解釈）。実験の結果によっては `llm_prompt_builder.dart` も変える
- 表示: `lib/l10n/app_{ja,en,zh}.arb` と `analysis_runner.dart`
- 実機テスト: `integration_test/on_device_llm_runaway_test.dart`、`docs/ios.md`
- 外部依存の追加はない。iPhone で暴走していた要求は、約20秒から数秒に縮む見込み
