# Proposal

## Why

iPhone（iOS 27.0.1）で Apple オンデバイスモデルによる用語要約を実行すると、最終要約が「〈記憶人〉…人口が少ない。」} 支援者: Appleです。 支援者: Appleです。 …」のように、同じ文を応答上限まで繰り返した壊れたテキストになり、そのまま要約として保存・表示された。

スキーマ制約付きの生成が guardrail に拒否されると、プロバイダはスキーマを外し greedy で再試行する。この再試行は「モデルが自分で回答を閉じて止まる」ことを前提にしているが、iPhone のモデルは止まらなかった。同じ事実・同じプロンプトでも、macOS 27.0.1 のモデルは止まり（拒否は3回中2回起きた）、iPadOS 26.6.2 でも問題は出ていない。OS の版ではなく端末ごとのモデルの違いであり、OS 更新で直るのを待つ問題ではない。さらに、パイプラインは読めない最終要約を生テキストのまま要約として保存するため、壊れた回答がそのまま読者に届く。

## What Changes

- **拒否されたら、まず制約付きでもう一度試す。** 拒否は確率的に起きる（macOS 27.0.1 で同じプロンプトが3回中1回は通った）。そこで、スキーマを外す前に同じスキーマでもう1回だけ生成する。スキーマを外す経路に入る回数そのものを減らす。1つのプロンプトに対する生成は最大3回になる（従来は2回）。
- **スキーマなしの再試行は、プロバイダが自分で打ち切る。** スキーマなしの再試行を逐次受け取り、最上位の JSON オブジェクトが閉じた時点で打ち切って、そのオブジェクトだけを返す。同じ文を繰り返し始めたら上限まで待たずに打ち切り、「回答が繰り返しに陥った」という独立した失敗として報告する。この失敗は再試行に値するものとして扱う。
- **BREAKING（全プロバイダ）: 読めない最終要約を要約として保存しない。** 最終要約が2回とも読めなかった場合（JSON として解釈できない）、生テキストを要約として保存・表示せず、要約を読み取れなかった理由を示して解析を失敗させる。2回目の要求そのものが失敗した場合も同じ扱いにする。Ollama・OpenAI 互換のプロバイダが地の文で答えた場合もこれに含まれる。Stage 1（事実抽出）の生テキストへのフォールバックは残す（キャッシュしないという扱いも変えない）。
- **iOS 実機の計測テストを追加する。** 今回のプロンプトを、アプリと同じ Dart プラグイン経由で実機のモデルに渡す integration test を用意する。修正前の再現と修正後の確認を同じ手順で行う。greedy と既定サンプリングの差、打ち切りにかかった時間も記録する。
- greedy サンプリングは維持する。打ち切りはサンプリング方式によらず効くため。サンプリングを見直すかどうかは計測データを見てから別途判断する。

## Capabilities

### New Capabilities

（なし）

### Modified Capabilities

- `apple-on-device-llm`: 拒否時の再試行の順序（制約付きでもう1回、そのあとスキーマなし）と回数の上限、スキーマなし再試行の打ち切り（オブジェクトが閉じた時点・繰り返しの検知）、新しい失敗の原因「繰り返し」とその再試行の扱い、スキーマなし再試行が返す形、応答上限との関係
- `llm-summary-pipeline`: 最終要約の生テキストへのフォールバックを撤廃し、読めない最終要約は失敗として扱う。生テキストへのフォールバックは Stage 1 に限定する

## Impact

- ネイティブ: `packages/foundation_models_llm/darwin/foundation_models_llm/Sources/foundation_models_llm/FoundationModelsLlmPlugin.swift`（逐次受信・打ち切り）。打ち切り判定は Flutter ビルドの外でテストできるよう、`packages/foundation_models_llm/darwin/wire_code_tests` と同じ方式の独立した Swift パッケージに置く
- Dart プラグイン: `packages/foundation_models_llm/lib/src/`（メソッドチャネルの引数、`OnDeviceGenerationFailure` への新しい原因の追加）
- クライアント: `lib/features/llm_summary/data/foundation_models_client.dart`（再試行の順序）、`lib/features/llm_summary/domain/llm_analysis_failure.dart`（再試行の扱い、新しい失敗型）
- パイプライン: `lib/features/llm_summary/data/llm_summary_pipeline.dart`（`_readableOr` と最終要約の解釈）
- 表示: `lib/l10n/app_{ja,en,zh}.arb`（新しい失敗の文言）と、失敗を文言に変換している箇所
- 実機テスト: `integration_test/`（新しい計測テスト）、`docs/ios.md`（実行手順）
- 外部依存の追加はない。オンデバイスでの生成回数は、最悪の場合に増える（design.md 参照）
