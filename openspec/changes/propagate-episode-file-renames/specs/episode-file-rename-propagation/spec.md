# Spec Delta

## Purpose

小説のダウンロードや更新でエピソードファイルがリネームされたとき、ファイル名で記録しているアプリ内の状態（読書進捗・本文位置・ブックマーク・TTS音声・LLM要約のキャッシュと履歴、表示中の選択）を新しい名前へ追従させ、読書の継続性を保つ。

## ADDED Requirements

### Requirement: リネームはファイル名をキーに持つ状態へ伝播する

ダウンロードまたは更新の処理がエピソードファイルを旧名から新名へリネームしたとき（ゼロ埋め幅の変化、タイトル変更のいずれでも）、システムはその小説について、ファイル名で記録している次の状態を新名へ付け替えなければならない（SHALL）。

- 読書進捗（最後に開いたファイルと、その本文内の位置）
- ブックマーク
- TTS で生成済みの音声
- LLM 要約の事実キャッシュ
- LLM 要約の履歴が指すジャンプ先

正規名のファイルが既にあったために旧名のファイルが削除された場合も、旧名から新名へのリネームとして扱わなければならない（SHALL）。

伝播は、リネームを行ったその小説のフォルダに属する状態だけに及ばなければならない（SHALL）。別の小説の状態や、同じ名前を持つ別フォルダのファイルを変更してはならない（SHALL NOT）。

#### Scenario: 総話数の桁上がりで読書進捗が保たれる

- **WHEN** 9話構成の小説を `9_x.txt` まで読み、読書進捗がそのファイルを指している状態で、小説を更新して12話になり、`9_x.txt` が `09_x.txt` へリネームされる
- **THEN** 読書進捗は `09_x.txt` を指し、本文内の位置も保たれる
- **THEN** 小説を開き直すと `09_x.txt` が開き、保存された位置へ復元される

#### Scenario: ブックマークとTTS音声が新しい名前で見つかる

- **WHEN** `3_x.txt` にブックマークと生成済みの TTS 音声がある状態で、更新により `3_x.txt` が `03_x.txt` へリネームされる
- **THEN** `03_x.txt` を開くと、そのブックマークと生成済みの音声がそのまま利用できる

#### Scenario: タイトル変更によるリネームでも伝播する

- **WHEN** 作者がエピソードのタイトルを変え、更新によってそのエピソードのファイルが新しいタイトルの名前へリネームされる
- **THEN** そのエピソードに付いていた読書進捗・ブックマーク・TTS音声・LLM要約のキャッシュと履歴は、新しい名前で参照できる

#### Scenario: 旧名ファイルが削除された場合も伝播する

- **WHEN** 更新時に正規名のファイルが既に存在したため、旧名のファイルがリネームではなく削除される
- **THEN** 旧名で記録されていた状態は、新名への付け替えとして扱われる

#### Scenario: 他の小説には影響しない

- **WHEN** ある小説の更新で `1_x.txt` が `01_x.txt` へリネームされ、別の小説にも `1_x.txt` という名前のファイルとその読書進捗がある
- **THEN** 別の小説の読書進捗・ブックマーク等は変更されない

### Requirement: 新しい名前に既存の記録があればそれを優先する

付け替え先の新名に既に記録がある場合、システムは新名の記録を残し、衝突する旧名の記録を破棄しなければならない（SHALL）。新名の記録は現在の正規ファイルに対して作られたものであり、旧名の記録より新しいためである。この方針はすべての保存先に共通して適用しなければならない（SHALL）。

衝突しない旧名の記録は、新名へ付け替えなければならない（SHALL）。

#### Scenario: 同じ位置のブックマークが両方の名前にある

- **WHEN** 旧名 `5_x.txt` の10行目と、新名 `05_x.txt` の10行目の両方にブックマークがあり、`5_x.txt` が `05_x.txt` へ付け替えられる
- **THEN** `05_x.txt` の10行目のブックマークは1件だけ残る

#### Scenario: 新名側に生成済みのTTS音声がある

- **WHEN** 旧名と新名の両方に生成済みの TTS 音声があり、旧名が新名へ付け替えられる
- **THEN** 新名の音声が残り、旧名の音声は削除される

### Requirement: 伝播はリネームの直後に行い、取得の結果に左右されない

システムは、リネームの伝播を各エピソードの取得より前に完了させなければならない（SHALL）。リネームは取得の前にディスク上で確定するため、以降の取得がキャンセル・失敗・成功のいずれで終わっても、伝播は既に行われていなければならない（SHALL）。

この伝播は、既存小説の更新に加えて、既に存在する小説フォルダへダウンロードし直す場合にも適用しなければならない（SHALL）。

#### Scenario: 更新をキャンセルしても伝播は済んでいる

- **WHEN** 更新でエピソードファイルがリネームされた後、新しいエピソードの取得中に利用者が更新をキャンセルする
- **THEN** 読書進捗・ブックマーク等は新しい名前を指している

#### Scenario: 更新が失敗しても伝播は済んでいる

- **WHEN** 更新でエピソードファイルがリネームされた後、エピソードの取得が失敗して更新がエラーで終わる
- **THEN** 読書進捗・ブックマーク等は新しい名前を指している

#### Scenario: ダウンロードダイアログからの再ダウンロード

- **WHEN** 既にダウンロード済みの小説の URL をダウンロードダイアログから再度ダウンロードし、ファイルがリネームされる
- **THEN** 更新の場合と同じく、読書進捗・ブックマーク等は新しい名前へ付け替えられる

### Requirement: 読書位置の保存待ちを失わない

リネームの伝播より前に、システムは保存待ちの本文内の位置を書き込まなければならない（SHALL）。また、表示中のエピソードの付け替えは、読書進捗の付け替えより後に行わなければならない（SHALL）。順序を誤ると、付け替え後の選択が別のファイルを開いたものとして記録され、本文内の位置が先頭に戻るためである。

#### Scenario: 読んでいた位置へ戻る

- **WHEN** あるエピソードの途中まで読み、その位置が保存待ちのまま更新を始め、そのエピソードのファイルがリネームされる
- **THEN** 付け替え後のエピソードは、更新前に読んでいた位置を保持している

### Requirement: 伝播の失敗はダウンロードを止めない

保存先ごとの付け替えの失敗は、WARNING レベルでログに記録しなければならない（SHALL）。失敗によってダウンロードを中断してはならない（SHALL NOT）。また、他の保存先の付け替えを妨げてはならない（SHALL NOT）。

まだ作られていない保存先（その小説で一度もブックマークや TTS 音声を作っていない場合など）は、付け替えのために新たに作成してはならない（SHALL NOT）。

#### Scenario: 一つの保存先の失敗

- **WHEN** リネームの伝播中に、ブックマークの付け替えが失敗する
- **THEN** WARNING がログに記録され、他の保存先の付け替えとダウンロードは続行される

#### Scenario: TTS音声を作ったことのない小説

- **WHEN** 一度も TTS 音声を生成していない小説が更新され、ファイルがリネームされる
- **THEN** TTS 音声の保存先は新たに作成されない
