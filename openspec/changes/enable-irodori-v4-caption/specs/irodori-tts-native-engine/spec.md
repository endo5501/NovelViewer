## ADDED Requirements

### Requirement: 尺補正オプションの受け渡し
C API は Irodori の尺補正パラメータを合成リクエストへ渡せなければならない (SHALL)。少なくとも「補正の有効・無効」「字数則の係数」「字数則の余白」を指定できなければならない (SHALL)。

現行の `audiocpp_synthesize` は固定引数のため、引数を無制限に増やさずに拡張できる形を採らなければならない (SHALL)。既存の呼び出し側がそのまま動作し続けること (後方互換) を満たさなければならない (MUST)。

未指定時はエンジン側の既定値 (補正無効) が使われなければならない (MUST)。すなわち、このオプションを渡さない呼び出し側の出力は変化してはならない (MUST NOT)。

#### Scenario: 補正オプションを渡して合成する
- **WHEN** 補正を有効にするオプションを付けて参照音声 + caption の合成を呼ぶ
- **THEN** 0 が返り、尺補正が適用された音声が取得できる

#### Scenario: 補正オプションを渡さない既存呼び出し
- **WHEN** 補正オプションを一切指定せずに従来どおり合成を呼ぶ
- **THEN** 補正は適用されず、従来と同じ長さの音声が得られる

#### Scenario: 不正な値
- **WHEN** 字数則の係数に負値を渡して合成を呼ぶ
- **THEN** 非ゼロが返りエラーメッセージが取得できるか、既定値にフォールバックする。異常な長さの音声を無言で生成することはない

### Requirement: 尺補正は caption から導出する
尺補正の有効化は、Dart の各層を貫いて運ぶパラメータとしてではなく、**caption を C API に渡す唯一の地点で
caption の有無から導出**しなければならない (MUST)。

理由は不変条件の担保方法である。「caption を渡すなら補正も渡す」を層をまたいだ受け渡しで守ると、
経路が増えるたびに守り忘れが起こりうる。すべての caption が通過する 1 箇所で導出すれば、
**caption を渡しながら補正を忘れることが構造的に不可能**になる。

したがって Isolate の合成メッセージ・セッション・各 controller に補正用のフィールドを追加しては
ならない (MUST NOT)。合成に到達する 3 経路 (ストリーミング生成・編集ダイアログの再生成・
保存済みセグメントの再合成) は、いずれも caption を渡すだけでよい。

補正の係数を将来ユーザ設定として公開する場合は、この導出地点に値を与える形で行い、
不変条件そのものは維持しなければならない (SHALL)。

#### Scenario: caption 付きの合成では補正オプションが付く
- **WHEN** caption を指定して Irodori 合成を呼ぶ
- **THEN** C API へ `duration_correction` が渡る

#### Scenario: caption なしの合成では補正オプションが付かない
- **WHEN** caption を指定せずに Irodori 合成を呼ぶ
- **THEN** リクエストオプションは空で、従来と同じ経路・同じ出力になる

#### Scenario: 空文字 caption は caption なしと同義
- **WHEN** 空文字の caption を指定して合成を呼ぶ
- **THEN** caption は渡されず、補正オプションも付かない

#### Scenario: 全経路で同じ扱いになる
- **WHEN** ストリーミング生成・編集ダイアログの再生成・保存済みセグメントの再合成のそれぞれから合成する
- **THEN** いずれも同じ導出地点を通るため、caption の有無だけで補正の有無が決まる
