## Why

iPad の narrow レイアウト（幅 800pt 未満。iPad mini 縦向きの 744pt など）では、ファイルブラウザは `Scaffold.drawer` の中にある。Flutter の `DrawerController` は閉じている間、子を `SizedBox.shrink()` に差し替えるため（`drawer.dart` の `_buildDrawer`）、ドロワーを閉じるたびに `FileBrowserPanel` の `State` が dispose され、`ScrollController` も一緒に破棄される。再表示時は新しい `ScrollController` がオフセット 0 で作られるので、リストは必ず先頭から表示される。

`FileBrowserPanel` には選択ファイルを画面中央へ寄せる自動スクロールが既にあるが、`ref.listenManual(selectedFileProvider, ...)` で「選択が別のパスへ変化したとき」だけ発火する。再マウント時は選択が変わっていないため何も起きない。

結果として、話数の多い小説を読んでいる最中にファイルブラウザを開くと毎回先頭に戻り、現在読んでいる話を見るために毎回スクロールし直す必要がある。

同じ再マウントは画面回転でも起きる。iPad mini を縦（744pt、narrow）から横（1133pt、wide）へ回すとレイアウトが切り替わり、パネルは作り直される。

## What Changes

- `FileBrowserPanel` に「マウント後の初回表示で一度だけ、選択中のファイルが見える位置までスクロールする」挙動を追加する。既存の `_scheduleScrollTo` のオフセット計算を再利用し、中央寄せの位置を使う。
- 初回だけはアニメーションではなく即時ジャンプにする。ドロワーのスライドイン（約 246ms）と 250ms のスクロールアニメーションが重なるのを避け、開いたときには既に目的の位置にある状態にする。選択が変化したときの既存のアニメーション付きスクロールは変更しない。
- 初回スクロールはマウントごとに一度きりとする。同じパネルが生きたままユーザーが別フォルダへ移動したときに再発火してはならない。フォルダを開いた直後は先頭から見えるのが正しい。
- 選択ファイルが無い場合、および選択ファイルが現在のフォルダに含まれない場合は何もしない。リストは先頭のままとする。

破壊的変更はない。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `file-browser`: 「Auto-scroll to keep the selected file visible」要件が選択変化時のみを対象としている記述を、マウント時の初回表示を別の発火点として切り出す形に改める。あわせて初回表示の挙動を定める要件を追加する。

## Impact

- `lib/features/file_browser/presentation/file_browser_panel.dart`: 初回スクロール済みフラグの追加、`_scheduleScrollTo` へのアニメーション有無の引数追加、リスト構築時の初回スクロール予約
- `test/features/file_browser/presentation/file_browser_panel_test.dart`: 初回表示のスクロール、未選択時に先頭のままであること、別フォルダ移動で再発火しないこと、ドロワー再表示での回帰テストを追加
- 既存の自動スクロールのテスト（選択変化時のアニメーション、同一ファイル再選択で動かないこと）は挙動が変わらないため、そのまま通過する必要がある
- wide レイアウト（デスクトップ、iPad 横向き）ではパネルが常駐するため、通常の使用では初回スクロールは起動直後の一度だけ走る。本アプリは起動時に前回の選択ファイルを復元しないので、起動直後は選択が無く実質的に何も起きない。効くのはレイアウトのブレークポイントをまたいだとき（画面回転、ウィンドウのリサイズ）である
